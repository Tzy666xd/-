# 2026-10-11 轮：新手引导关（第一课是一局真牌局）

上一轮做的是**路过提醒**（`core/tutorial.ts` 七条气泡）。这一轮做的是用户新提的那件事：
第一次玩的时候先上一关课，把规矩和机制讲清楚。两者的分工写在 `core/guide.ts` 的头一段：
提醒是"路过你旁边说一句"，引导关是"站住，这一步做给我看，我再讲下一步"。

## A. 为什么是一门"课"而不是一叠弹窗

三条轴定死了形状，都是这个项目已有的尺子：

1. **上的就是一局真牌局**。种子、牌组、难度、模式全锁死（`GUIDE` 那行），
   开局走的仍是界面里同一个 `start()`——不搞第二套开局代码，也就不会有"教学局里学的和实战不一样"。
2. **纯投影**。某一节该不该出现、算不算过，全由课程表里 `open(f)` / `done(f)` 读已经算好的状态得出。
   玩法一律不读 `state.guide`。`selftest` 里那条硬判据是：同一颗种子，**全程上过课的局与没上课的局
   逐位相同**——牌序、流水、`rand.calls`（随机数被取用了多少次）、账本行数、日志长度全等。
3. **不拦人**。课程不锁任何按钮、不替玩家出牌。你没做这一步它只是不往下走；
   「这一步我先跳过」「退出引导」两颗键随时在。窗口设计（`open`）是这门课不卡死的关键：
   一把就打穿第 1 场的人，"一场要打好几手"那节自动翻页，不会被按着头再讲一遍。

十节课的顺序：讲线 → 弃牌 → 凑牌型 → 出牌 → 一场要打好几手 → 请第一位客人 → 抬注 →
货架上不止有客人 → 客人逐个开口 → 结业。前两节在第 1 场牌桌边讲完，中间三节跨结清幕，后四节在铺子与第 2 场。

## B. 固定种子不是随手挑的

第 5、6 节课要在铺子里"请一位客人"，请不起就整门课卡住；第 2、3 节课要第 1 场还没被打穿，
一把穿掉就得自动翻页。**发牌顺序只要被改动**（换随机数、改 `freshDeck`、改 `setupStage`），
这些前提就可能一夜之间不成立，而内核自检看不见课程、界面门禁跑得又慢。

于是有了 `tools/guide-check.mjs`：一个**按课程表行事的机器人**把整门课走一遍，判三件事——
每节该出现的课都出现了且顺序就是课程表顺序；每节要求的动作机器人都当场做出来了；
走完全程没散局、请得起客人、抬得起一注。它还带 `--search`，用来在种子失效后找替补。

实测结论（种子 20261011 / 手松档 / 标准牌组）：

```
board(看过) → swap(弃1次) → shape(three) → cash(+126) → hire(payne£3) → raise(×1)
  → shelf(看过) → pulse(1位客人+56) → done(看过)
自动翻页：drive
```

## C. 这一轮抓到的东西（四条都是真 bug，不是测试自己的坑）

1. **教完的课会回头再教一遍**。多数课的"做到了"读的是**瞬时**状态：选了哪几张、铺子开没开。
   牌一打出去选择清空，`lessonFor` 就退回上一节，屏幕上重新出现"凑一个真牌型"。
   修法是加一层记账（`claimGuide`），做到即写进 `state.guide`。
2. **记账不能往后扫着记**。第一版 `claimLessons` 遍历整张表，凡 `done` 成立就记掉——
   于是第 8 节"带着客人再打一手"（判据是本场出过牌）在**第 1 场**就被记掉了，
   等玩家真请完客人出完牌，那节课已经不讲了。改成**一轮只记当前那一节**：
   从前往后找到第一节没记过的、窗口开着的课，它做到了就记它，没做到就停在那里。
   界面和自检模拟的是同一条规则，两边才可能对得上。
3. **铺子里点完东西不重投影，那两节课就挂在屏上**。请客人和抬注都只调 `renderShop()`
   不调 `renderAll()`，而气泡的投影挂在 `renderAll` 上——做完了没反应，比不教更糟。
   在 `renderShop()` 末尾补一次 `refreshTutorial()`。
4. **气泡只夹横向不夹竖向**。铺子的货位区很高，"往下放"把整块气泡推出了屏幕外：
   看不见的气泡等于没有气泡，还占着 z-index 75。placeCoach 现在纵向也夹。

测试自己的坑也记三条，因为它们都会伪装成产品 bug：

- `__H.select(n)` 是**切换**而不是设置：选完再调一次等于把牌点回去。
  第一版走查里"出牌"那步就是这么静悄悄没打出去的，界面表现为"20 秒还在 busy"。
- `saveNow()` 有 120ms 防抖。查"进度活进了存档"之前不等一下，读到的是上一版，判据会假红。
- 弃牌那条路径没有 `busy` 可等（它只 `await` 自己那组动画）。所以走查里改成等
  "这一节被记进进度"那一刻——那是唯一诚实的完成信号，而不是按秒数瞎猜。

## E. 顺手补的两条门禁缺口（都是这轮跑测时踩出来的）

1. **界面反证的停摆复跑认不出"节流"**。本轮一次全跑里「跳过演出」红了：
   空格跳过实测 1412ms（正常 ~150ms），而"不跳过"的基线 1564ms 完全正常——
   跳过生效了（标记收回、没留快放痕迹那两条判据都过），只是定时器被整秒对齐了（App Nap / 负载）。
   原来的复跑判据只认 `-1ms|卡在|没给出裁决`，这种"活着但慢"漏网。
   现在 uitest.js 会把这种形状标成 `疑似时钟节流`，uitest.sh 见到就改代打时钟复跑这一档。
   这条新判据用 `uitest=skip&fakethrottle=1` 证明过它会红：
   `UITEST FAIL 27/31 [跳过演出] …【疑似时钟节流：定时器被整秒对齐，改代打时钟复跑】`，
   再 `&vclock=1` 复跑则 `PASS 27/27` 并显式记 2 条「未评」。
2. **`falsify-ui.sh` 的条目数与文档不一致**：文档写 58，实际数组里是 54 条（`bash -c 'source; echo ${#INJ[@]}'` 数出来的）。
   本轮把它改成以脚本实测为准。另外记两个 bash 坑：数组字面量里的 `#` **不是注释**，
   会被当成条目（本轮就因此报了 4 条 BAD）；条目文本里的 `${...}` 与反引号必须转义。

## F. 等用户拍板的（我先按"能交付"选了一边）

1. **老用户要不要被这张课表拦一次**。`prefs.guide` 缺键我按"第一次玩"处理（`o.guide === true`
   才算上过课），所以升级后第一次启动会看到课表卡。另一边是"缺键当作老玩家、不拦"。
   现在还没有装机量，我选了"拦一次"——漏掉一门课比多点一下「我自己开一局」更亏。
2. **课表卡要不要写"约两分钟"**。实测走完十节课（含两次演出）在 8–12 秒之间，
   写着两分钟像劝退，不写又像藏话。当前卡片写的是"先在牌桌上坐两分钟"，等你定。
3. **教学局要不要留档**。上完课这一局就是普通的一局，可以继续打完八夜，存档照写。
   也可以设计成"课上一完就散场，另开正式一局"——那要新写一条散场路径，目前没做。
4. **第十节课（结业）钉在牌桌正中**。它讲的是"往后怎么办"，没有具体部件可指。
   如果你觉得正中那块碍事，可以改成钉在彩头线上，或者干脆做成一张小卡。

## F2. 出图这一侧学到的两条（都跟"窗口没上屏"有关）

1. **CSS transition 在无头窗口里不走**。`.overlay` 靠 `transition: opacity .5s` 淡入，
   所以"从 hidden 切到可见"的那张卡（第一课课表卡）在 `--shot` 里永远是透明的——
   截图看着像没渲染。牌桌样张不受影响是因为它们走 `snap=1`，那条规则把 transition 全关了。
   于是课表卡样张的查询串是 `snap=1&intro=1`：`refreshIntro` 平时在 snap 下不弹这张卡
   （不然每张牌桌样张都被它挡住），`?intro=1` 是明确点名"我就是来看它的"。
2. **抓帧的钩子必须排在 autostart 之后**。`?lesson=1`（一步落在第一节课）最初放在
   `if (autostart || SNAP) { start(...) }` 之前，结果 snap 抓帧时先开课、再被普通局顶掉，
   样张里什么都没有。挪到那段之后才对。这类"顺序错了看着像功能坏了"的坑，
   判据抓不住，只有真出一张图看一眼才知道。

## G. 门禁自己也要跑得动（这一轮把界面扫描从 3 小时压回 30 分钟）

新加的「引导关」档要真点击走完十节课，整趟套件从 ~2 分钟涨到 ~4 分钟；
反证扫描每条注入都要跑一遍套件，69 条就是 3.5 小时。两处一起改：

1. **`speed=12`**：这一档判的是课程翻页与气泡几何，不判手感，
   把演出时间轴压快十倍之后单档从 110 秒降到 2.7 秒，判据一条没少。
   （手感归「跳过演出」「演出路径」两档管，它们不许压。）
2. **`STOP_FAIL=1`**：反证扫描只问「这处破坏有没有让门禁变红」，
   第一档红了就收工，不必把十二档都跑完。uitest.sh 的裁决与退出码不变，
   falsify-ui.sh 仍在注入前跑一次完整基线。

整趟套件 41 秒、六十九条注入约半小时——慢到跑不动的门禁等于没有门禁，
这条和"判据必须会红"是同一件事的两头。
