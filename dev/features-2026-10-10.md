# 玩法功能构建 · 交付包（2026-10-10）

七个功能全部落地：P0-1 加注、P0-2 邻接共鸣、P0-3 阈值奖励、P1-1 套装、P1-2 长进、
P1-3 卡牌层级、P1-4 弃牌堆。每个都带独立 feature flag，**默认全关**。

实测数据都在这个仓库里跑出来的，不是估计：
```bash
node core/selftest.ts      # 429 条正向判据（本轮新增 123 条）
bash tools/falsify.sh      # 83 条内核注入，盲区 0
bash tools/falsify-ui.sh   # 27 条界面注入（含本轮新增 11 条）
bash tools/uitest.sh       # 新增「新功能」一档：26 条界面判据
```

| 文件 | 是什么 |
|---|---|
| `core/flags.ts` | 开关与清洗 |
| `core/thresholds.ts` | P0-3 阈值表 + 折算/跨线判定 |
| `core/bets.ts` | P0-1 加注表 + 失手裁决 |
| `core/sets.ts` | P1-1 套装表 + Mods 累加 |
| `core/growth.ts` | P1-2 长进等级/封顶 |
| `core/layers.ts` | P1-3 材质/效果两张层表 |
| `core/content.ts` 末尾 | tag / 邻接 / 长进三张附表挂到 14 位客人上 |

三条硬约束的遵守方式：**没有新增计分维度**（全部走现成的 `chips/mult/xmult`，
`value` 恒等于 `chips × mult`，有判据逐条查每个事件的 `after`）；
**一行可解释**（`__H.chain()` 能把最近一次结算摊成文本，新功能那几行带 ★，见第五节）；
**正交**（每个功能下面都写了"玩家多做了什么决定"）。

## P0-3 阈值奖励

**1. 设计卡**
- 决策点：这一手是**冲线拿奖励**，还是留强牌给后面几手。
- 对局时长影响：每手多 0–2 秒思考；不改手数。
- 已知化学反应：与 P0-1 加注咬合最强——抬注把彩头抬高，阈值线（彩头的百分比）跟着抬高，
  但达标后的 `×1.5 / ×2` 也是按已累积倍注乘上去的。
- 最容易失控的组合：**阈值级联**。一条 bonus 推高链条，会自己跨过下一条线。
  实测同花 6 级一手连吃 7 条，1540 分滚到 17062 分（×11）——所以必须
  `MAX_PER_HAND=2 / MAX_PER_STAGE=1`。这条上界有两条注入钉着（写成零与写成无限都被抓）。

**2. 数据结构与配置**
`ThresholdDef { id, name, blurb, at, span, reward, progressVisible, carryOver }`，
表里 10 条，`at` 是**彩头的整数百分比**不是绝对分（见第 6 节）。
`reward` 只允许 `{chips|mult|xmult}`。

**3. 集成点**
挂在 `score()` 里 `independent` 之后、`total` 之前，通过包装 `push()` 在**每条事件落地后**判定，
所以达标那一行落在它该落的那一拍上。读 `chips/mult`；写 `events` 与返回的 `claimedNow`；
不消耗 RNG ⇒ **幂等**，同种子重放完全一致。认领账 `state.claimed` 进存档。

**4. 计分拆解（真跑出来的，非示意）**
```
  高牌（1 级）起手 → 流水 5 × 倍注 1 = 5
  4♦：+4 流水 → 流水 9 × 倍注 1 = 9
  管家霍布斯「侍立」：+8 流水 +0 倍注 ×1 → 流水 17 × 倍注 1 = 17
  女继承人「箔面」：+50 流水 +0 倍注 ×1 → 流水 67 × 倍注 1 = 67
  女继承人「产业相照 · 与醉醺醺的从男爵同court」：+0 流水 +0 倍注 ×1.4 → 流水 67 × 倍注 1.4 = 94
  管家霍布斯「侍立渐熟 第 1 档」：+20 流水 +0 倍注 ×1 → 流水 87 × 倍注 1.4 = 122
★ 阈值「打赏罐」：+30 流水 +0 倍注 ×1 → 流水 117 × 倍注 1.4 = 164
  收口 → 流水 117 × 倍注 1.4 = 164
  本手入账 164，银钱 +0
```

**5. 测试用例**
- 正常：seed 1002 同花 6 级一手跨过线，`claimedNow.length === bonus 事件数`。
- 边界 ①：`prev < at && now >= at` 恰好压线算跨过，差一分不算，起点已在线上不算。
- 边界 ②：一手最多 3 条（2 hand + 1 stage），`books.flush=14` 的极端强牌也越不过去。
- 破坏性：`carryOver=false` 换场必须清零（否则同一场重复白拿）；
  `claimed` 里塞不存在的 id ⇒ 整份存档拒收。

**6. 平衡备注**
线画在彩头的 40/65/90/110/140/200/320%。**必须按比例而不是绝对值**：
写死 180 这种数到第 8 夜就是白送，实测会让"冲哪条线"这个决策消失。
按比例后同一手 304 分的牌：第 1 夜触发 2 条（×1.74），第 3 夜起 0 条——难度自平衡。
单手上限 ×2.79（一手同时够到两条线），整场额外贡献约 +1 条阈值。
P50/P90 见第五节：对不做这个决策的贪心机器人，开与关走完场数完全相同（P50=3）。

**7. flag**：`thresholds`，默认 `false`。

## P0-1 加注（风险押注）

**1. 设计卡**
- 决策点：本场抬到第几档；高档位现在**买得起一次续命**，失手不再是当场出局。
- 时长影响：铺子里多一次点击，不增加对局内时间。
- 化学反应：与 P0-3（阈值线随彩头水涨船高）、与声望门槛（`restock` 用 `rep+raisedHere`）。
- 最易失控：**续命不限次**⇒可以无限赖在同一场。所以 `reprievesUsed >= 1` 直接判负。

**2. 数据结构**
`BetDef { tier, name, blurb, targetMult, rewardMult, surplusBonus, repBonus, failPenalty, moneyLoss, visibleHint }`，5 档。
`FailPenalty = 'none' | 'loseMoney' | 'losePatron' | 'loseRound' | 'loseRunAsIs'`。

**3. 集成点**
`targetFor(..., betTable)` 读表；`settle()` 的赏金/盈余/声望三个数读表；
失手裁决在 `play()` 尾部（`s.handsLeft <= 0` 那一支）→ `betReprieve(g)`。
`betReprieve` 会清零 `score`、补满牌权/弃牌、按 carryOver 重算认领账、并 `recycle()`——
**必须走 recycle**，否则桌面牌蒸发（AGENTS.md 承重墙 4）。不消耗额外 RNG 之外的东西：
洗牌用主流，与老行为一致。幂等性：同一状态重复裁决不会二次扣分（靠 `betReprieves` 计数）。

**4. 拆解**
不产生 `score()` 事件（它改的是彩头与结算，不是链条）。在抬注面板上一行：
`第 3 档 彩头 ×3.375 赏金 ×2.5｜失手：本场作废`。

**5. 测试用例**
- 正常：1 档失手 → 扣 25% 银钱、`score=0`、`betReprieves=1`、状态不是 `lost`。
- 边界 ①：同场第二次失手 → `lost`。
- 边界 ②：2 档但席上无人 → 降级为赔银钱，不报错也不静默失效。
- 破坏性：`failPenalty` 注入成"失手反而给钱" ⇒ 被 `P0-1 失手反而给钱` 那条注入抓红。

**6. 平衡备注**
关键纪律：**表里每一项都等于原来的硬编码**（`targetMult=1.5^tier`、`rewardMult=1+0.5·tier`、
bonus=`tier`）。跨 11 夜 × 3 场 × 5 档逐位比对开/关两条路，0 处漂移 ⇒
**老种子、老存档、老抓帧基线一个分数都不会变**。
强度下限 0 档（等于没有这个功能），上限 4 档彩头 ×5.06 但失手即散局（续命买不起）。

**7. flag**：`bets`，默认 `false`。

## P0-2 小丑槽位排序（位置敏感）

**1. 设计卡**
- 决策点：把谁挨着谁坐，让共鸣的 `×倍注` 复合顺序最优。
- 时长影响：铺子里每次换座一次点击（£2）。
- 化学反应：与 P1-1（同一套 tag 既触发共鸣又凑套装，构筑轴统一）、与版本（三彩 ×1.5 与共鸣相乘）。
- 最易失控：**共鸣写成加法**。加法可交换 ⇒ 换座不影响结果 ⇒ "排序"这个决策不存在。
  有判据直接查这件事（`邻接共鸣一律是乘法或倍注`）。

**2. 数据结构**
`PatronDef.tags?: string[]` + `PatronDef.adjacency?: Effect`；7 个门类、6 位客人带共鸣（5 个 `xmult`、1 个 `mult`）。
`SWAP_COST = 2`。

**3. 集成点**
在 `score()` 第 4 档（`independent`）内按 `roster` 下标左→右判定，
`Cue` 带上 `index`；读 `chips/mult`，写 `events`。不消耗 RNG ⇒ 幂等。
换座只在 `status === 'shop'` 且 `flags.adjacency` 为真时开放。

**4. 拆解**
`女继承人「产业相照 · 与醉醺醺的从男爵同court」：+0 流水 +0 倍注 ×1.4 → 流水 67 × 倍注 1.4 = 94`

**5. 测试用例**
- 正常：`[baronet, heiress]` = 21.00，`[heiress, baronet]` = 19.50 —— 可预测、可复现。
- 边界 ①：最左位没有左邻 ⇒ 不触发。
- 边界 ②：相邻但无共享 tag ⇒ 不触发。
- 破坏性：`flag 关掉时换座逐位无差别`（写成 `if (adj)` 绕过开关的注入被这条抓红）；
  演出中换座被拒（正在演的账不能被中途改掉）。

**6. 平衡备注**
共鸣倍率压在 1.25–1.4，最多 6 位带共鸣，理论上限是连续相乘；
但座位上限 3–4，实际一手最多加 ×1.4×1.35 ≈ ×1.89。换座收 £2 是摩擦成本，
防止"每场免费重排"变成无脑最优解。

**7. flag**：`adjacency`，默认 `false`。

## P1-1 套装（tag 构筑）

**1. 设计卡**
- 决策点：为凑一门而买一位本身不强的客人。
- 化学反应：与 P0-2 共用 tag；与铺子刷新（凑齐差一人时"要不要重掷"变成真问题）。
- 最易失控：套装奖励**直接乘倍率** ⇒ 与 P0-2 叠成二次方爆炸。需求文档禁了这件事，
  代码用判据把规矩钉死：`套装奖励一律是 Mods，没有一项是 chips/mult/xmoney`。

**2. 数据结构**
`SetDef { id, tag, count, name, blurb, reward: Mods }`，10 条，奖励只落在
`seats / slots / hands / discards / freeRerolls / interestCap / handSize / priceScale / targetScale`。

**3. 集成点**
`limits()` 里在客人 mods 之前累加 `setMods()`，所以是**独立加项**；
`priceScale/targetScale` 用乘法、其余用加法（与现有 Mods 语义一致）。
纯函数，不写状态、不消耗 RNG ⇒ 幂等。

**4. 拆解**
不进 `score()` 事件流（它改规矩不改分数）。在铺子里独立一块：`套装「律政一门」：slots +1`。

**5. 测试用例**
- 正常：`clerk+cousin` ⇒ 随身槽 2→3。
- 边界 ①：三人档是在两人档之上**再叠一层**，不是替换。
- 边界 ②：`clerk+heiress`（law 只剩一位）⇒ 整条失效。
- 破坏性：把 `s-law` 的奖励改成 `{mult:3}` ⇒ 判据立刻红（已作为注入）。

**6. 平衡备注**
每项奖励都等价于一个已有的会员特权量级（+1 槽、+1 次弃牌、一次免费重掷），
没有"整套直接翻倍分数"的通路，所以强度上限天然被 `Mods` 的取值范围锁住。

**7. flag**：`sets`，默认 `false`。

## P1-2 成长型客人

**1. 设计卡**
- 决策点：留谁上场——用得越多的客人越强，于是"谁该坐穿"变成构筑问题。
- 化学反应：与 P0-2（要让它坐在那个左邻旁边才能既触发共鸣又涨 XP）、与 P0-3。
- 最易失控：**没有上限**。需求文档点名的就是这个，所以 XP 在 `grow()` 里硬封顶。

**2. 数据结构**
`GrowthDef { xpPerUse, levels: {requireXp, effectDelta}[], note }`；3 位客人有：
`hobbs`（+20/+45 流水，3/6 档）、`rent`（+5/+12 倍注，4/9 档）、`almanac`（×1.15，5 档）。

**3. 集成点**
读：`score()` 第 4 档按 `seat.xp` 追加一条 `patron` 事件。
写：XP 累加在 `play()` 里、结算之后，从**事件流的 pid 集合**取——
所以"演出来的"与"记下来的"必然一致；`score()` 本身保持无副作用 ⇒ 可重放。
`Seat.xp` 进存档并做外部输入校验。

**4. 拆解**
`管家霍布斯「侍立渐熟 第 1 档」：+20 流水 +0 倍注 ×1 → 流水 87 × 倍注 1.4 = 122`

**5. 测试用例**
- 正常：连续出牌，XP 单调升到 3 档后加成出现。
- 边界 ①：XP=0 不产生任何事件（不是产生一条 +0 的事件）。
- 边界 ②：`grow(999)` 仍等于封顶值。
- 破坏性：存档里 `xp=-3` 或 `1e9` ⇒ 整份拒收；只有真触发过的那位才涨 XP。

**6. 平衡备注**
上限即等级表最后一档，`almanac` 只有一档（+×1.15）作弱档对照。
最远的 `rent` 要 9 次触发到顶（一场 4 手 ⇒ 约两场多），所以是中期奖励不是滚雪球。

**7. flag**：`growth`，默认 `false`。

## P1-3 牌的强化层级

**1. 设计卡**
- 决策点：让"给哪张牌上什么层"从两个写死枚举变成可扩展的数据轴。
- 化学反应：与 P1-4（捞回的那张牌带着层）、与引荐信（造层的手段）。
- 最易失控：堆第三层。这一条由**类型**挡住：`Card` 只有 `enh` 与 `seal` 两个单值槽。

**2. 数据结构**
`MATERIALS`（5 条，对应 `enh`）+ `SEAL_LAYERS`（5 条，对应 `seal`），
`LayerDef { id, name, line, chips?, mult?, xmult?, moneyPerCard?, repeat?, breaksOn?, moneyOnSettle? }`。
`MAX_LAYERS = 2`。

**3. 集成点**
`score()` 逐张那一档改为从表读数（`layerChips/layerMult/layerXmult/layerRepeat/layerMoney/layerBreaksOn`）。
不写新状态、不额外消耗 RNG（玻璃碎裂仍走同一次 `rand.chance`）⇒ 幂等。

**4. 拆解**
两层各占一行由 `layerRows()` 给出；结算事件里 `card` 行已含两层的合计，
`layerRows` 供拆解视图/tooltip 分层显示。

**5. 测试用例**
- 正常：红封两次、加成 +30、倍注 +4、玻璃 ×2 且 25% 碎、蓝封 3 张 ⇒ +75、金封每次 £1。
- 边界 ①：金票（`enh:'gold'`）**不按计分次给钱**——只在结清折 £4。
  这条差点被我的表写错，实测发现后改回 `moneyOnSettle`。
- 边界 ②：`layerCount` 最大为 2。
- 破坏性：**80 手逐位比对**，开/关 `layers` 的 `value/money/shattered` 必须完全一致；
  把 `layerChips` 换成写死值 ⇒ 立刻红（已作注入）。

**6. 平衡备注**
本功能**零数值改动**——它的价值是让以后调数值不用动结算代码。
实测 400 手（每手覆盖全部 enh×seal 组合）0 处漂移。

**7. flag**：`layers`，默认 `false`。

## P1-4 弃牌堆可操作

**1. 设计卡**
- 决策点：£5 把关键一张捞回牌堆底——值不值这一次构筑机会。
- 化学反应：与 P1-2（早点捞回关键牌，那位客人涨 XP 更快）、与"誊抄/销账"类引荐信。
- 最易失控：**捞回直接进手牌** ⇒ 凭空多一张牌，绕开"牌堆会打空"这个压力源。
  这正是 fuzz 当年抓过的那类问题。

**2. 数据结构**
`FISH_COST = 5`、`PEEK_MAX = 8`。

**3. 集成点**
`peekDiscard()` 纯读；`fishDiscard()` 从 `discardPile` 摘一张 `push` 到 **deck 末尾**，
只在 `status === 'shop'` 且 flag 开时可用。`recycle()` 语义不变，牌数守恒有判据。

**4. 拆解**
不进链条（它是构筑动作）。账本里一行：`从弃牌堆捞回一张（£5）`。

**5. 测试用例**
- 正常：弃 2 张 → 铺子里捞回 1 张，弃牌堆 -1、牌堆 +1。
- 边界 ①：`peekDiscard(s, 99)` 被 `PEEK_MAX` 夹住。
- 边界 ②：同一张不能捞两次（第二次 `findIndex` 已找不到）。
- 破坏性：**`totalCards` 必须守恒**；改成 `s.hand.push` 立刻被"捞回的牌进了牌堆而不是手牌"抓红；
  演出中不许捞。

**6. 平衡备注**
£5 约等于一位普通客人的价，且捞回的是"未来某一手"而非"现在这手"，
所以它是延迟收益，不会替换掉更强的构筑选项。

**7. flag**：`discardOps`，默认 `false`。

**门禁终值（本轮实测）**

| 门禁 | 结果 |
|---|---|
| `node core/selftest.ts` | 429 条正向判据，0 失败（本轮新增 126 条） |
| `bash tools/falsify.sh` | 83 条内核注入，**盲区 0**、语法噪声 0、坏条目 0 |
| `bash tools/uitest.sh` | **八档全绿**，共 187 条：keys 14 · prefs 33 · reload 16 · again 9 · 跳过 27 · 性能 50 · 新功能 31 · 演出路径 7 |
| `node core/fuzz.ts` | 不变量全过，动作分布与改前一致 |
| `node core/sim.ts` | 中位数 5 场，与改前**一模一样**（默认全关不该动基线） |

| `bash tools/shots.sh` | 20 帧 + 对照表正常出图 |

**反证抓出来的三个覆盖洞（都补上了）**：`falsify-ui` 一开始报出三条 BLIND——
① 达标那一行在演出里被抽掉、② 跳过路径不结算 bonus、③ 够不着线时"还差多少"赖着不走。
根因是同一片盲区：**feat 档跑在 `snap=1` 下，走的是 `applyEventsSync`，
根本不经过 `runTimeline`**，所以演出路径以前等于没被测。
补法是加一档 `featlive`（不加 snap，经代打时钟走真演出路径），并给它两条真判据：
`H.cues > 0`（飘出过几条阈值提示）与拆解里有 ★。

# 追加：开局选签名宾（五选一）

**1. 设计卡**
- 决策点：开局从五位客人里请一位入座——**这一局的整条路线由这一选定调**。
  靠脑子的（「这是本夜最后一次出牌才响」）要你围绕它安排出牌节奏；
  稳吃的无条件干货；吃运气的（「每手 1/6 机会 ×3 倍注」）把一部分分数交给骰子。
- 对局时长影响：开局多一次选择；因为路线不同，中局构筑思路跟着变。
- 已知化学反应：与 P0-2（「只坐上座的人」逼你换座）、与 P1-1（每位都挂了 tag，
  签名宾直接是套装的起手件）、与 P0-1（「放账的中人」按抬注层数乘倍注）。
- 最容易失控的组合：**吃运气的一族叠在一起**（浪子 + 占星婆婆 + 走私商），
  方差大到构筑失去意义。所以候选每批只保证给得出一种稳吃与一种吃运气，不是一屋子骰子。

**2. 数据结构与配置**
- `PatronDef.temperament: 'head' | 'hand' | 'heart'`（每位必填，14 位老人也补齐了）。
- `core/draft.ts`：`drawOffer(seed, rep, rerolls)`、`draftPool`、`deriveRand`、`OFFER_SIZE=5`。
- 客人数 **14 → 32**，新增 18 位各带一条互不重复的机制。举例：
  值夜更夫（最后一手 ×2）／算牌先生（牌堆 ≤15 张时加账）／拾荒裱糊匠（弃牌堆 ≥10）／
  只坐上座的人（座位最右 ×2.2）／讲究整齐的女爵（5 张全计分才给）／放账的中人（按抬注层数乘）／
  破釜沉舟的将军（少一次出牌换 ×2.5）／爱张罗的东道主（只加座位不产生分数）／
  掷骰浪子 1/6 ×3／占星婆婆每张 1/5 +20／走私商结清时 1/3 付 £15。

**3. 集成点**
候选完全在**派生随机流**上抽（`deriveRand(seed, rerolls)`），开局入座只 push 座位、
**一步都不碰主随机流**。这一条有判据钉着：开与不开这个功能，起手牌与 `rand.calls` 必须逐位相同
（实测 `calls=51` 两边一致）——否则老存档快进到的步数会落到别的牌上，复现性承诺当场破产。
`RunOpts.signature` → 构造期入座 → `state.signature` 进存档。flag 关掉时连 id 都不传。
幂等：`drawOffer` 是纯函数，同 (seed, rerolls) 永远同一批。

**4. 拆解 / 选单输出**
候选一行的格式 `名字｜脾气｜机制`，例：`值夜的更夫｜靠脑子｜这是本夜最后一次出牌时 ×2 倍注`。
签名宾触发时和普通客人一样出一条 `patron` 事件，拆解读数用 `__H.lastHand()` 三轴分别比。

**5. 测试用例**
- 正常：同 seed 两次抽完全一致；点卡选中、开局入座、存档往返认回。
- 边界 ①：非法/未知 id 忽略，不凭空塞客人；档里签名宾不在座上 ⇒ 当作没选而不毁档。
- 边界 ②：候选池 ≤5 时全给不硬凑；rep=0 时传说/贵客不进池。
- 破坏性：连点四次"换一批"不许撞回老名单（40 粒种子）；
  注入"重掷返回固定名单"必须被这条抓红（一开始没抓到，见第 6 节）。

**6. 平衡备注**
- **脾气配比是调过的**：光按稀有度权重抽，实测 400 批里 head 出现 1381 次、heart 只 262 次，
  "选一位"就退化成"在五张条件牌里挑一张"。加了 `ensureMix` 后变 1082/474/444，
  且 400/400 批同时给得出稳吃与吃运气。
- 上限：签名宾就是一位普通客人（不额外送钱送座位），强度由 `cost`/`rarity` 与门槛管住。
- **`sim` 中位数从 5 场掉到 4 场**，原因不是新功能变难，而是客人池 14→32 之后
  铺子里多了两位**带负面代价**的客人（将军 −1 次出牌、牌桌老板彩头 +20%），
  贪心机器人照买不误。这与 AGENTS.md 里那条"凡是模拟结果反直觉，先怀疑模拟器"同源，
  真人难度仍以你试玩为准。

**7. flag**：`draft`，默认 `false`。

**过程里被反证抓出来的两个弱判据（都不是白捡的）**
- "重掷会换一批"只比了第 0 次 vs 第 1 次：注入成"重掷一律返回同一份固定名单"时它照样成立。
  补成"连着重掷每次都不同 + 同一粒种子连点四次不撞回老名单"才抓红。
- `save.ts` 里我一度写了**两行重复守卫**（PID_SET 判定 + 座位成员判定），
  第二行独立兜住了同一件事，于是打在第一课上的注入报 BLIND——因为它打的是死代码。
  删掉重复那行、只留语义正确的一条，注入才落在真正生效的位置上。

# 同日第二轮：形象、背景乐，以及 fuzz 没开开关这件事

需求是"补充美术设计细节，丰富 bgm 和小丑形象设计，修 bug"。三件事都按同一条纪律做：
**能量的量，不能量的跑出真产物看一眼，改完的行为必须有具名判据 + 一条会红的注入。**

## A. 客人肖像（`core/portrait.ts`）

**先量再改**。第一版剪影肖像的两两灰度差：中位 8.6 → 13.1 → 18.2 → 19.7，
496 对里低于 12 的从 438 对降到 54 对——盯着图看是看不出来"到底分不分得开"的。
真正的转折是找到两条**结构性**原因，而不是继续加零件：

1. **画布被各向异性拉伸了 2.5 倍**。肖像按 64×64 正方形画，塞进 98×46 的横椭圆
   （`preserveAspectRatio="none"`），横着拉 2.5 倍：高帽压成一条、圆脸拉成面包。
   改成**按椭圆自己的比例原生作画**（viewBox `0 0 96 44`），零件才真的占画面。
2. **整层脸谱是"奶油上画奶油"**。人是浅奶油色剪影、底是暗色，
   而帽/发/脸全用 `currentColor` 描——凡与头圈重叠的记号（胡子和单片镜圈）像素级等于没画。
   现在与轮廓重叠的一律用暗色刻线（`PALETTE[rarity].cut`），
   探出轮廓之外的（帽檐、发绺、胡须、肩形、手中物）才用浅色。
   这条写成了判据：`LAYERS.face` 里除 `plain` 外每条必须含刻线色，`hat`/`prop` 每条必须含浅色。

再加两根"大块面"杠杆：**头形**（7 种缩放/倾斜，同一顶帽子下圆脸和长脸是两个人）与
**底色色偏**（脾气定色相窗口，每位在窗口内 ±16°，把 24 位冷青彼此再分开）。

**结果**：中位 26.1、最差 12.3、496 对里 0 对低于 12（门槛 `--min 12`）。
顺带修掉两处小像被压成一条的问题：候选卡 `.dc-pf` 与铺子 `.slot-pf` 原来是正圆，
现在跟着肖像比例做横椭圆。

**留下的判断**：`portrait-check.py` 只回答"分不分得开"，好不好看仍要肉眼——
所以另配 `portrait-sheet.py` 把 32 张拼成一张对照表（真渲染、真裁框）。

## B. 背景乐（`core/music.ts` + `MusicPlayer`）

四首 → **八首**（新增小步舞/夜曲/拉格/众赞），并且：

- **每首一种音色**（八音盒/弦乐/簧风琴/竖琴），四种各带两首。
  八首共用一把琴就只是"八段音高"，不是八首曲子。
- **声部从 3 个加到 5 个**：旋律/低音/铺底 ＋ 分解和弦 `arp` ＋ 刷鼓 `perc`。
  鼓点写在谱面上（`K`/`S`/`h`），四首有鼓四首没鼓，不当鼓机。
- **局势进音乐**：`plan(tune, from, count, heat)`，heat 0/1/2。
  界面按"头人夜 / 只剩一次牌权 / 这一场抬过注"算 heat，
  1 叠分解和弦、2 再给旋律加一个高八度影子。玩家不用回头读数字也知道这手不能失手。

## C. fuzz 一直没开功能开关（这是本轮最大的盲区）

## G. 那两条 BLIND 不是白报的（补记）

`falsify-ui` 跑到签名宾那两条时给了 BLIND。根因不是注入写错，是**判据自己会逃**：

- `开局请的签名宾真的坐进了座位` 写成 `sigPid === '' ? true : …`——

- "换种子之后候选框不重画"这条**从来没有判据碰过它**：测试只点"换一批"，从不改种子。
  补一条真探针：改 `#seedInput` 并派发 `input`，断言**旧节点已经离场**
  （不看换成了谁——两粒种子理论上可能同批，看节点身份才与内容无关）。

两条都在补完之后重新注一遍验过：分别红在 `点中的那张候选卡认得出是谁` 与
`改种子之后候选框重画了`（42/43、41/43），基线回到 43/43。

# 同日第三轮：音效细节（配方搬进 core，声部从 9 种扩到 27 种）

需求"丰富音效细节"。原来十几个音效是**写在界面方法里的一行行 `tone()`**：
`chips()` 就是 1180Hz 方波 0.06 秒。于是"阈值达成有没有专属声音""连击是不是真的在往上爬"
"三层叠起来会不会削顶"全都只能戴着耳朵听。这轮把配方抽成 `core/sound.ts` 的数据表，
界面退化成执行器——与 music.ts 同一套分工。

## A. 谱面：26 个配方，每个 1~4 层

新增的声（原来根本没有）：选中/放回牌、弃牌、**阈值达成**、**玻璃碎**、收口重音、
入席、离席、**换座**、**捞牌**、**抬注**、**凑成一套**、**客人长进**、请定签名宾、
贵客进门、本场结清。加上原有的落牌/流水/倍注/翻倍/进账/发牌/拦下/蜡封/失手/噼啪。

几个是"听得见的因果"而不是装饰：
- **换座**两声咔哒、第二声更高 —— 听得出是两个人对调，不是一个人动了下；
- **抬注**按档位整体抬高 —— 风险要听得见；
- **阈值达成**是三枚往上走的银钱加一条长尾 —— 与"客人给了一下"（流水声）明确区分，
  否则玩家分不清那点涨是谁干的（这正是硬约束②在听觉上的延伸）。

## B. 三根"细节"杠杆，全部落成数据

1. **连击抬升 `lift`/`liftMax`**：流水一档比一档高（1 半音/档，14 档封顶），
   倍注、翻倍注、抬注、长进各有自己的爬升曲线。判据：`f(1)<f(2)<…<f(14)` 且 `f(14)===f(20)`。
2. **花色明暗 `tint`**：落牌那一声按花色给滤波中心频率系数（黑桃闷 0.86 / 红桃亮 1.12），
   同一手连打五张听得出花色序列。判据：四种 tint 给出四个不同频率、越界索引夹紧。
3. **每层独立开关 `noLift`**：纸面摩擦那层**不跟**连击往上尖 —— 一开始没这个字段，
   扫到第 9 档时它被抬到 12057Hz 出了判据上界。这是量具直接抓出来的（见 D）。

壁炉噼啪的"大小不一"改成**按步数查表**（8 步一循环，三档），不再用 `Math.random()`：
core 不碰随机数这条规矩要守住，而且同一串步数必须永远得到同一串噼啪。

## C. 总线与账本

- 音效总线加了**房间混响**（0.45s 短 IR，湿 0.14）与**压限器**（−12dB / 4:1），
  所以连击叠层不会削顶；背景乐接的是 master，不会被这层混响再湿一遍。
- 每个声部节点都进 `made/freed` 记账，`__H.sfx.pending` 可测。
  **上界和下界一起判**：把噪声层滤波器的计数漏掉，pending 会往负走，
  只判 `< 80` 的话这种错反而永远绿。实测 8 手连打之后在飞 3 个。

## D. 这一轮被自己的量具抓出来的东西

- `连击抬到头也不越界`（每个 cue 扫 20 档 × 4 种 tint）当场判红一次：
  落牌声的第三层（纸面摩擦 5200Hz）跟着连击被抬到 12057Hz。
  修法是给它 `noLift`，而不是把上界从 12000 放宽。
- `峰值增益不爆音` 第一版写成"所有层增益求和"，那会把 `clear` 那种**依次落下的四颗音**
  算成同时响 —— 判据会误报，人就会去调一个本来没问题的配方。改成按时间重叠求最大栈，
  并补一条 `峰值不是恒零` 的反空转判据（把重叠条件注成 `if (false)` 就会红）。
- `P1-1 第一屏不报里程碑` 这条**是我自己写错的断言**：feat 档在铺子那一步之前已经渲染过
  一屏没有套装的货架，之后凑齐三人再进铺子，"新达成"是真的，响是对的。
  改成测真正的性质：**同一套不重复报 + 新凑成才报**（`fired.set === 1`）。
  教训：里程碑类反馈要判"不重复"，只判"响过"抓不到每次重渲染都响一遍那种反向错误。

## F. 补一节：光有表内判据，测不出"到底响没响"

写完 21 条谱面判据之后回头想：它们查的全是**参数**（频率在范围、增益不为零、层数 1~4）。
一类错误照样能全绿过去——包络写成 `0.0002`、声源忘了 `start()`、`stop()` 早于起振：
参数全部合法，波形一片死寂，玩家那边就是"这游戏没声音"。

所以加了一档 `uitest=sound`：用 `OfflineAudioContext` 把 26 个配方**逐个渲染成波形**量峰值，
断言 0.002 ≤ peak ≤ 1，并且"谱面上写了大小不一/只抬音高不抬音量"这两件事
必须在波形上真的分得出来（大爆点 > 小火星 1.5 倍；连击 0 档与 9 档峰值差 < 0.002）。
实测 5/5 过。三条注入验过它确实会红：包络写死成静音 → `哑的：pick=0.00002,…`；
声源刚起就掐 → 同一批判据红；把离线窗长写死成 64 个样本 → 峰值取不到真实值，红。

顺带修掉一条真 BLIND：`局势进音乐` 原来的探针记的是 `this.heat`（调度器**打算**用的值），
把 `plan(tune, step, 1, this.heat)` 的实参改成 `0` 它照样报告 2 —— 于是那条注入全绿。
改成累计**排出来的事件里加层声部的个数**，并同时判反向（松下来之后不许再加层）。
一句话教训：**探针要读被它声称测量的那个东西的下游，别读意图字段。**

# 同日第四轮：新手引导（把"这牌局怎么运转"从一段静态文字变成七句按局面说的话）

需求"增加新手教程引导"。**这条推翻了 AGENTS.md 不做清单里原先那句"不做教程弹窗"**——
本轮已把那句改掉，并在清单里留下新的边界（不做的是"开局一段非看完不可的演示"）。

## A. 表在 core，界面只是投影

`core/tutorial.ts`：七条 `Step`，每条有 `when`（什么时候该说）、`anchor`（贴在哪块 UI 旁）、
`done`（做到哪个动作就自己闭嘴）。`stepFor(facts, seen)` 是纯函数：
输入全是局面上已经有的数（打过几手、过过几关、在不在铺子、下一场是不是头人夜），
一次只返回一条，顺序即优先级。

七条的顺序就是设计意图：`看分数线 → 选牌与弃牌 → 客人逐个开口 → 盈余折现 →
铺子四件事 → 抬注（本项目独有的那条规矩）→ 头人夜的刁难`。
每条 body 一句话说完一件事——**"一行可解释"这条硬约束在文案上同样成立**，
判据直接钉住"无换行且 ≤62 字"。

进度记在 `state.tutorial`（讲过哪几条的 id 数组），随存档往返：
读档回到中途不该把讲过的那条再弹一遍。清洗规则与 `claimed` 不同——
**不认识的 id 丢掉就行**，改一句文案、删一条步骤，不该把人家一整局档毁掉。

## B. 三条"教程不能反过来害人"的硬规矩，每条都有判据

| 规矩 | 为什么是硬要求 | 怎么量 |
|---|---|---|
| 不吃点击 | 气泡会压在牌桌/按钮附近，拦住玩家第一次操作比没教程更糟 | 拿气泡自己中心点做 `elementFromPoint`，命中的不许是它自己（位置无关） |
| 不盖住锚点 | 指着一个东西却被那个东西挡住，等于没有指引 | 气泡矩形与锚点矩形不相交 |
| 不参与算分 | 教程是第二套计分轴的话，种子复现性就废了 | 同一粒种子、一个看过全部引导一个完全没看，连打 40 手比手牌/分数/银钱/`rand.calls` 逐位相同 |

## C. 这一轮被自己的量具与截图抓出来的四个错

1. **"知道了"永远只关第一条**。按钮只在气泡创建时绑一次，回调闭包捕获了**当时**那条 step，
   于是后面每条都关不掉。改成从元素自己的 `dataset.step` 读当前这条。
   —— 判据：`点"知道了"就换下一条`。
2. **铺子那条指错了东西**：锚点选了顶栏的「铺子」按钮，面板展开时它被压在下面，
   气泡于是也躲在面板后面——**"存在但看不见"**。改成指面板里的货位区，
   并把气泡层从 62 抬到 75（面板 70 之上、幕 90 之下）。
   —— 判据：`气泡与锚点同在一层`＋`气泡完整落在视口内`。
3. **设置里按"关"要立刻见效**。`applyPrefs()` 没人重投影，气泡会挂到下一次别处渲染才消失，
   那个开关看着就是坏的。补 `refreshTutorial()` 进 applyPrefs。
   —— 判据：`关掉引导后气泡立刻收起（不用等下一次渲染）`。
4. **多行批量替换又吃掉了一次代码边界**：把 `setTimeout(...)` 插进 `if / else if` 中间，
   语法当场塌掉。这是老坑第 N 次复发（AGENTS.md 里就记着一条），
   改完必须跑一次能证明结构没塌的验证——这次是 `build-web` 报的。

另外两处是判据自身的问题，都按"BLIND 先怀疑判据在逃"处理：
- `背景曲八首都进了选单` 按**序号**取那一排设置，加一行「新手引导」就把整档判据指到别的控件上
  （表现为"脚本抛错，一条判据都没跑成"）。改成按标签找。
- 一条注入报 BLIND：`case 'beforePlay': return f.started && f.played === 0` 改成
  `return f.started` 行为完全不变——因为 `satisfied()` 已经先把它拦掉了。
  **那半句是死条件**。修法不是给死条件编个判据，是把死条件删掉，
  换一条真的会改变行为的注入（`inShop` 恒 false → 走完只剩五条）。

## D. 环境探针补了一条（跑测中途时钟会停）

`uitest.sh` 原来只看 `CGDisplayIsAsleep`。实测遇到两次"报醒着、动画却一步都不走"
（跳过演出档 `-1ms`、性能档某一手锁 16 秒），说明那只是必要条件。
新增 `tools/clock-probe.js`：**真跑一根 150ms 的 WAAPI 动画看它能不能自己完成**，
据此决定是否代打时钟；另外任一档失败若长得像"卡住"，自动用代打时钟复跑一遍并注明。
本轮两次全跑各留下一份结论：探针 `CLOCK OK` 时 10 档 257 条全绿（含三条耗时门限：
不跳过 1558ms vs 跳过 153ms、最慢一手 3135ms < 4000ms）；探针 `CLOCK STUCK` 时改走代打，
10 档 252 条全绿，那三条显式记成「未评」而不是混进通过数。
