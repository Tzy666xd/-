# 决策记录

四位编号从 0001 起。改承重墙必须先在这里加一条，并写清"代价"和"怎么验"。

## ADR-0001 · 玩法与界面用 TS，Swift 只做壳

**决定**：内核与渲染全是 TypeScript + DOM/CSS；Swift 侧只有一个 WKWebView 壳
（`app://local` 自定义 scheme、目录穿越防护、无头 `--shot`）。
**原因**：① 这个项目的难点是动效密度与排版密度，不是 3D 或粒子；那 7 条 juice 手法
（数字滚轴、分级震屏、因果级联、常驻后处理、卡牌抬升）本来就是 CSS 的原生语言。
② 用户预留 iPhone 版，要求"渲染/逻辑内核抽成跨平台共享包"。
③ 潮屿当年从 JS 原型移植到 Swift（其 ADR-0026）的驱动因素是 3D 越肩镜头 +
`SCNRenderer.snapshot` 无窗口出图，卡牌 2D 不存在这个因素；那次移植的真实代价是
13 条断言逐条重验一遍。
**代价**：Swift 侧的 selftest 反证范式不能直接照搬，无头验证要分两层（node 验内核、
壳的 `--shot` 验画面）。
**验证**：`node core/selftest.ts` 与 `bash tools/shots.sh` 两条链都要绿。

## ADR-0002 · 计分输出可重放的事件序列，不是单个数

**决定**：`score()` 返回 `ScoreEvent[]`，每个事件带 `after: {chips, mult, value}` 快照。
**原因**：原版最值钱的手感是"客人严格从左到右逐个触发、每次脉冲后暂停、再更新累计值"，
约 300ms 一场，把复合乘法演成因果剧，等于免写教程。这要求计分是序列而不是一次求和。
晚改会推翻整个渲染层，所以第一天就定死。
**代价**：结算代码比"直接算个总分"长；`after` 快照要保证每步都自洽（已进判据）。
**验证**：`selftest` 里"每条快照自洽 value=chips×mult""流水/倍注单调不减""逐张按打出顺序"
三条判据；`falsify.sh` 有对应注入。

## ADR-0003 · 零构建：用 Node 自带类型擦除，不装 tsc

**决定**：源码写 `.ts`。Node 直接跑（自检），浏览器侧用 `module.stripTypeScriptTypes`
擦类型输出 `web/gen/*.js`。不引入 npm 依赖。
**代价**：源码里禁用 `enum` / `namespace` / **构造器参数属性** / 装饰器，跨文件类型必须
`import type`。（构造器参数属性这条我自己踩了一次。）
**验证**：`node tools/build-web.mjs` 后 `grep -rn "\.ts'" web/gen/` 必须为空。

## ADR-0004 · 引擎同步权威，UI 只是投影仪

**决定**：`play()` 直接把分数入账并返回事件；动画只重放，不参与规则判定。
**原因**：避免"动画演到一半玩家乱点"改坏账本，也不需要 pending/commit 两套状态。
**代价**：状态已经跑到动画前面，渲染层判断"牌还在不在场"时必须小心（见 ADR-0005）。
**验证**：账本、银钱、声望都只由内核改；UI 里没有任何一处写 `g.state.score`。

## ADR-0005 · `settle()` 不清桌面

**决定**：过关只记 `status='cleared'`，`s.table` 留给下一场 `setupStage()` 收。
**原因**：实测踩过——`settle()` 里顺手 `s.table = []`，而 `place()` 用 `hand ∪ table`
判断元素是否还在场，于是**过关那一手的牌在动画中途被从 DOM 删掉，看着像凭空消失**。
**代价**：桌面会多留一屏牌直到下一场，但这本来就更符合"赢家留在桌上"的直觉。
**验证**：`selftest` 两条判据（结清后牌仍在桌 / 下一场开局才收）+ `falsify.sh` 一条注入。

## ADR-0006 · 无头抓帧走 snap 模式，FLIP 不用 rAF

**决定**：`?snap=1` 关闭全部 transition/animation，按结算事件序号同步落定视觉状态；
FLIP 用强制回流提交起点而不是 `requestAnimationFrame` 收尾；`wait()` 在 snap 下立即 resolve。
**原因**：窗口没上屏时 WebKit 的动画时钟与 rAF 是冻结的，但 `takeSnapshot` 仍按当前 DOM
重画。后果是过渡停在起始值（遮罩关不掉）、FLIP 把牌永久留在"平移回旧位置"那一帧。
**代价**：snap 帧拍不到真正的中间态（过渡被关掉），只能拍"逻辑第 N 步"的画面。
真机手感仍要用户试玩判断。
**验证**：`bash tools/shots.sh` 的逐帧差异表——相邻帧差异为 0 说明渲染层没在反映事件。

## ADR-0007 · 经营闭环是产品主张，不是装饰

**决定**：三条咬合——盈余转本金、**玩家主动抬注**、声望门槛；外加一页账本把曲线外化。
**原因**：这是与原版的关键差异点。原版只能被动接受盲注目标；把"要不要把风险抬高"
做成玩家自己按的按钮，才有经营感。账本则延续用户偏好的"把抽象东西做成可观察机制"。
**代价**：彩头曲线多了一个玩家可控变量，平衡比原版难拿捏——需要试玩数据。
**验证**：`selftest` 里抬注/利息/盈余折现/声望四项都有精确数值判据（不是 `>=` 糊过去）。

## ADR-0008 · 换场统一回收：弃牌堆 + 桌面 + 手牌

**决定**：`recycle()` 把 `discardPile`、`table`、`hand` 三者全部并回牌堆再洗，
`setupStage` 只负责发满手，不再自己清桌面。
**原因**：fuzz 抓到两个独立后果。① 只回收弃牌堆 → 每打一手牌就有几张**永久蒸发**，
牌堆耗干后玩家"没牌可出又没牌可弃"，原地卡死；② 不回收手牌 → 上一夜剩的牌挤占新一夜的
手牌位，`drawTo` 一进门就撞上"已经满了"直接不发了，贵客「窄桌」压上限到 5 完全失效
（实测手牌还是 8 张）。
**代价**：无。这本来就是正确模型。
**验证**：`换场后牌数守恒`、`换场重新发满一手`、`窄桌开场就把上限压到 5` 三条判据，
加 `falsify.sh` 里对应的两条注入。

## ADR-0009 · setupStage 先定贵客、再取限额

**决定**：`s.bossId` 的抽取必须在 `const lim = limits(s)` 之前。
**原因**：贵客会改手牌上限与出牌次数。顺序反了，`lim` 拿到的是没有贵客的旧值，
惩罚整个落空——而且**只断言 `limits()` 的测试抓不到**，因为事后 `limits()` 是对的。
必须断言"真实发到手上的数"（`hand.length`、`handsLeft`）。
**代价**：无，只是顺序敏感，注释里写死了原因。
**验证**：`findBoss('narrow')` / `findBoss('miser')` 各找真种子断言实际发牌数与实际出牌次数。

## ADR-0010 · 破坏性内容要有下限，牌尽则判负

**决定**：「销账」在 `totalCards <= MIN_DEALABLE(5)` 时拒绝执行；换场时若一张牌都发不出来，
直接判负而不是留在牌桌上。
**原因**：销账与玻璃碎裂都会**永久移出**牌。随机策略实测可以把整副牌拆到 0 张，
玩家会卡在一个既不能出牌也不能弃牌的界面上。
**代价**：极端构筑下少赚几次 £5。
**验证**：`拆到下限就拒绝再销账`、`换场无牌可发直接判负`、`牌打光且无牌可补时判负而不是卡死`。

## ADR-0011 · App Sandbox 下 WKWebView 不导航：是这台机器的 OS，不是这个 App

> **两次更正。** 初版写「`WKURLSchemeHandler` 与 App Sandbox 不兼容」——错。
> 第一次更正写「最小探针在沙盒下能过，所以问题在这个 App 的 bundle」——**那条控制组是无效的**：
> 当时的"探针"是 `.build/release/SandboxProbe` 这个**裸 Mach-O，不在任何 .app 里**。
> 裸二进制连 GUI 会话都进不去（重跑 16 秒零输出，既不 OK 也不 FAIL），它"通过"从来没被测到过。
> 这次把探针包成最小 .app 再跑，结论就翻了。

**同一台机器（macOS 27.0.1 / 26A434，非正式发布种子）上的实测矩阵**：

| 配置 | 结果 |
|---|---|
| 真 App bundle，无沙盒（ad-hoc） | ✓ |
| 真 App bundle，真证书 + 硬化运行时，无沙盒 | ✓ |
| 真 App bundle + App Sandbox（ad-hoc / Apple Development 都试了） | ✗ 导航永不完成 |
| **最小 bundle**（只有 Info.plist + 一句 `loadHTMLString`）+ 沙盒 | ✗ **同样永不完成** |
| 最小 bundle + 沙盒 + 去掉私有 KVC | ✗ |
| 最小 bundle + 沙盒 + 去掉硬化运行时 | ✗ |
| 最小 bundle，无沙盒 | ✓ `NAV OK` |
| 裸二进制 + 沙盒 | 无输出，不构成对照（这就是当初那条假控制） |

**所以**：拦住的是"沙盒里的 app bundle 起 WebContent 进程"这一件事，与下列全部无关——
自定义 scheme handler、`WKScriptMessageHandler` 注册、私有键 KVC（外壳现在已经完全不碰）、
entitlements 的具体内容、硬化运行时开关、签名身份（ad-hoc 与真证书结果一致）、以及本 App 自己的任何代码。
一个只有 12 行 Info.plist 的空壳 App 也能复现。

**判断**：这是 **26A434 这个系统种子上的沙盒/WebKit 组合问题**，不是架构问题。
`log show` 在这台机器上回溯不到 WebContent 相关条目，所以拿不到"被什么拒了"的直接证据——
这也是为什么这条只能靠矩阵夹逼。

**下一步（给后来的人，别在这台机器上继续挖）**：换一台跑**正式发布版 macOS** 的机器（或 CI 的
macOS runner），把 `/tmp` 那套最小 bundle 重跑一遍。要么它直接过（那 MAS 就是通的，本条作废），
要么它仍不过（那这就是个已知的平台限制，MAS 路线要换 `loadFileURL` + 容器内资源目录，
或换非 WebKit 渲染）。在拿到那个结果之前，**不要**再往本 App 的代码里找原因。

**已做的缓解**：
- 外壳加了导航超时，且**覆盖所有加载路径**（早先 `--probe-blank` 的超时注册在 `return` 之后，
  于是空白探针永远不超时、永远不退出——那几次"看起来卡死"其实根本没被测到）。
- 外壳彻底去掉私有 KVC：`isInspectable`（13.3+）与 `underPageBackgroundColor` + `layer.backgroundColor`。
  这本来就是审核驳回点，与沙盒无关也该做。
- `shell/Sources/SandboxProbe` 留在仓库里；复现要**先包成 .app**，脚本化的最小包法见本节矩阵。

**对本机的影响**：无。本机双击走 ad-hoc 无沙盒，Developer ID 分发走"真证书 + 硬化运行时 + 不沙盒"，
两条都实测能跑。MAS 提交这条路目前**无法在这台机器上验证**——注意这个措辞：
不是"已证明不兼容"，是"这台机器给不出结论"。

## ADR-0012 · 界面层要有自己的可证伪门禁，内核自检覆盖不到"代码不在执行路径上"

**背景**：第 6 轮 bug 审查时，内核 227 条判据全绿，而界面层同时躺着 6 个用户必踩的问题：
启动路径上根本没有 `prefs = loadPrefs()`（所有设置重启即失效）、`refreshResume()` 没在开场调用
（"继续上一局"永远不出现）、炉火 `setInterval` 被误装进牌组按钮的 click 闭包（点一次多一个永久定时器）、
`prefs.speed` 从没接到 `speedMul`（"节奏"那排是死按钮）、五排设置都不落盘、改音量后静音按钮文案与实际脱节。

**根因**：一次脚本化批量编辑用多行锚点做 replace，把启动段整块"切"进了点击回调。
代码没丢、语法没错、类型也没错——只是**不在执行路径上了**。这类问题：
- 读代码容易漏（它就在那儿，只是没人调用）；
- 内核自检永远看不见（它不碰 DOM）；
- 抓帧也看不见（`shots.sh` 一律 `snap=1` 自动开局，绕过了标题页与设置面板）。

**决策**：加一条与 `falsify.sh` 对称的界面门禁。
- Swift 外壳加 `--uitest <js>`：导航完成后在真 WKWebView 里 `evaluateJavaScript`，
  以返回值前缀 `UITEST PASS` 决定退出码。跑的是随包发布的那份代码，不是另一套被测物。
- `tools/uitest.js` 按 `?uitest=keys|prefs|reload|again` 分四档，**只点真按钮、发真 KeyboardEvent、读真 DOM**，
  判据看可观测状态（`__H.muted`、`dataset.style`、`#btnResume.hidden`、`localStorage` 里的 JSON），不看内部变量。
- `tools/uitest.sh` 用 `--boot` 在文档级摆 fixture（真存档 / 真偏好 / 清空），保证每档从零开始、可复现。
- `tools/falsify-ui.sh` 把这 6 个 bug 逐个注回去，要求每一处都让门禁变红（当前 9 条注入零盲区）。

**放弃的方案**：接 Playwright / 任何 npm 测试框架——与 ADR-0003 的零依赖纪律冲突，
而且被测的会是"dev server 上的页面"而不是 `.app` 里那份。

**连带修掉的工具缺陷**：`--probe-blank` 的导航超时注册在 `return` 之后，导致空白探针永不超时也不退出，
之前几次"看起来卡死"其实根本没被测到（见 ADR-0011）。无头工具只要可能静默挂住，就必须自带超时。

## ADR-0013 · 缓冲回合：每位开局自带一次免费重做

**决定**：`GameState.buffer` 初值 `START_BUFFER = 1`，打输本场时**先于** `betReprieve` 消费——
免费兜底优先于付费续命。消耗后重置分数/出牌次数/弃牌次数/手牌索引/选中项，
调 `recycle(g)` 重抽手牌，状态回 `playing`（手牌空则直接判负）。
**不重新抽贵客**：这是同一场的重打，不是新的一场。

**背景**：handoff §10 第 2 条只写了"加上缓冲回合"四个字，没说归属、次数、先后。
当时分叉两条路：（A）像 `betReprieve` 一样做成加注档的付费续命——但那要先定加注粒度，
而加注粒度本身还是未决项，等于把一个决定绑在另一个决定上；（B）开局自带、人人有、免费。
选 B 的理由：① 字面最直——"加"上去的东西默认是给所有人的；
② 与 `betReprieve` 正交，两者各管各的，不会互相污染判据；
③ 不需要先定加注粒度就能落地。

**代价**：默认给的兜底会"救活"一些本来该输的场次，`sim.ts` 中位场次从 4 → 5。
这是**预期内的**——缓冲回合就是干这个的；下界判据（"不规划构筑也能到 5 场"）同步上移，
不是 bug。真正要盯的是：它不能变成"无限赖场"，所以消耗必须递减（判据已钉），
且用光后照原样散局，不偷偷再给一次。

**先后顺序的讲究**：缓冲回合排在 `betReprieve` **之前**。
如果反过来，付费续命会先被触发，缓冲回合永远轮不到——那它就等于不存在，
判据"开局带 1 个、用掉就没了"会直接红。顺序是这条 ADR 最容易被改坏的地方。

**验证**：
- `selftest` 新增 13 条：开局带 `START_BUFFER` 个、消耗递减、分数重置、手牌补满、
  不收钱不占座、第二次失手才散局、零缓冲直接散局、存档快进后 buffer 一致、
  buffer 越界被拒收。
- `falsify.sh` 新增 1 条注入：`s.buffer -= 1` → `s.buffer -= 0`（缓冲回合不递减），
  要求自检报 FAIL。
- 5 条已有判据（裸输路径 / betReprieve 隔离 / 一般对局）把 `buffer` 置 0 后重跑，
  保证"关掉缓冲"与"原来的行为"逐位一致——否则默认给的兜底会污染老判据。
- `fuzz`：60 局 3441 步全过，"崩过一次(已续命)×148"里 buffer 与 betReprieve 各救各的，
  真·牌尽而亡仍是 60（buffer 不掩盖牌堆耗尽）。



## ADR-0014 · 随机事件：五十条数据表 + 一个执行器，不是五十个函数

**决定**：`core/events.ts` 只写"发生什么"（`EventDef` + 15 种 `EventOp` 的数据），
`core/game.ts` 的 `applyEventOp` 是唯一动 state 的执行器。事件每夜至多递一次，
在本夜第 2~3 次动作（出牌与弃牌合着数）之后把三张候选挂到 `state.pendingEvent` 上；
玩家点一张，或按「让牌局自决」由内核按 稳吃 → 靠脑子 → 吃运气 挑一条。
候选池走**派生随机流**（`deriveEventRand(seed, night, 已递次数)`），执行时的运气
（抛硬币、随机挑牌）走**主随机流**。

**背景**：用户要"五十个随机事件、三选一、可以系统代选、有偏策略有偏运气、甚至可以往牌组里
加特殊牌，设计大胆些"。分叉的地方是"事件写成回调还是写成数据"。

**为什么必须是数据**：
1. 存档是外部输入。回调进不了 `save.ts` 的白名单，也过不了"读档后这一局还是那一局"那条承诺。
2. 判据要能逐条钉。数据能写"这条 op 真的改了那格账"，函数只能写"调了一下没炸"。
3. 反证要能注。注掉 `applyEventOp` 里某个分支，必须有具名判据变红；注掉一个闭包里的三行，
   门禁只会报"文件跑不起来"（那是 NOISE，不是发现）。
4. 界面只投影：卡片上那三行字全部从 `ops` 推导（`eventTags`），不另存一份描述——存两处必漂两处。

**为什么派生流抽候选、主流管运气**：候选是"给你看哪三件事"，它换了顺序不该把发牌挪位；
而事件真的落地之后这一局本来就不一样了，它消耗的随机步数就该记进 `(seed, calls)` 的账。
这条分工有硬判据：同一颗种子，开着事件与关着事件的**第一手逐位相同**（含 `rand.calls`）。

**代价与不做清单**：
- 特殊牌只用**现有的** 5 种强化 × 5 种火漆那几轴，不新增 enum。新 id 会让"关掉 layers 也要同分"
  那条 80 手对照断掉，而且在没有 layers 的那条路上根本没有执行者——一张什么都不做的牌
  比没有这张牌更糟。
- `score` 那类 op **只许带流水/倍注/倍注乘，不许带银钱**。钱进管道要走哪条路是 §10 第 3 条
  还没定的产品决定，不该由一个功能替它定了。自检有一条判据专门盯着这件事。
- 每夜一次是上限，不是配额：前置条件不满足（钱不够、座位满、牌堆到顶）就不递，
  下一次动作再试，而不是硬塞一条玩家应不下来的事。

**验证**：`selftest` +68 条（表自洽 10、候选与派生流 8、触发与拦截 6、关掉==不存在 4、
进管道 5、逐类操作 18、存档 7、随身格守卫 3、牌堆守恒 1 等）；`falsify.sh` +18 条注入；
`falsify-ui.sh` +7 条；`uitest.sh` 新增「随机事件」档（真点击走三选一 + 自决 + 存档 + 教学局不弹 + 结算回顾）。


## ADR-0015 · 局长：钉设计终点，让曲线弯过去，而不是给每档重写一条曲线

**决定**：`core/lengths.ts` 是局长唯一的账。3～15 夜共 13 档，每档写死一个**设计终场彩头**
（最后一夜贵客局要做到的分，8,000 → 3,330,000，约 1.65 倍递增），从它反推终点系数
`lengthScale`，再由 `nightScale(nights, night)` 让**每一夜的系数从 1 线性弯到那个终点**。
八夜是参照档：分子分母同为 100,000 ⇒ 系数正好 1 ⇒ 那一档的账与加局长之前**逐位相同**。
局长经 `limits()` 的 `targetScale` 进账，和难度同一层，垫在客人/特权/事件之前。
`state.nights` 由 `clampNights` 保证是 3..15 的整数（构造口、存档、偏好三处同一把夹子）；
判胜读 `s.night >= s.nights`；开局候选按局长偏置（`draft.ts` 的 `lengthWeight`），
但**六到九夜恒为 1**。**两处锁死**：每日一局锁八夜参照档；引导关锁最短三夜（2026-10-12 他定"引导关轮数少一些"，
钉在 `core/guide.ts` 的 `GUIDE.nights`，见 ADR-0016）。

**背景**：用户要"普通模式可以自定义打牌轮数，三到十五轮，设置一定的阈值，不同轮数对应的
最终目标不同，不同轮数开局选择的小丑也略有不同"。"轮"经确认折算成**整局长度（夜）**。
分叉的地方有两个：终点是设计值还是公式的副产品；缩放是整条乘一个数还是弯向终点。

**为什么终点必须是设计值**：写成公式（例如"每多一夜 ×1.65"）会让 13 个数字变成一条曲线的
读数，改任何一处都要重算全部；写成表则"这一档该难到哪里去"是一个**可以被单独否决的设计决定**，
自检只核对"最后一夜的彩头确实等于表里那个数"。第一版试过整条乘系数：八夜参照曲线本身是陡的
几何增长，整体缩放把两端都拧坏——十五夜第一夜只剩 40 分（白送一夜），三夜第一夜要 600 分
（短局反而更狠，与"短局是场遭遇战"相反）。弯向终点之后人人从同一个 300 起步。

**为什么锁死那两处**：引导关十节课的翻页时机是按某一档排好的，跟着玩家的轮数走会把课上到
一半就散场；每日一局的卖点是"全机同一天同一局"，局长不锁的话同一天的两个人终点不一样，
那句话就只剩牌序了。两处都有判据，且界面那一排锁住时**高亮落回真会跑的那个数**
（屏幕上不许亮着一个不会跑的数字）。

**代价与不做清单**：
- 局长**只改目标线**，不改发牌、不改规矩、不改经济：同一颗种子在 3 夜与 15 夜起手逐位相同
  （有判据）。想做"短局给更多银钱/长局多给一次牌权"那类，得先过 §10 那条钱的决定。
- **不做** 15 夜以上，也**不做**每档独立曲线：那样八夜之外每一档都是另一个游戏，没法比对。
- **不做**局长专属奖励（成就、声望加成、独立牌组）。要不要给短局一个"快局奖章"是产品决定，
  写进 §10 等他拍。
- 长档在无尽里靠"过了终点就固定按终点系数弯"兜住。**这条是上线前量出来的坑**：
  长档终点系数小于 1，线性外推会在第 20 夜上下穿过零，彩头变成负数（"打输"也算过线）。
  判据是 13 档各推到第 30 夜，彩头必须全为正且一夜比一夜高。

**验证**：`selftest` 701 → 735 条（表自洽、13 档终点、第一夜同为 300、档内单调、无尽外推、
判胜落在所选夜数、局长不碰随机流、存档往返/旧档/坏档、候选偏置方向、每日一局锁死）；
`falsify.sh` 175 → 189 条（14 条新增，盲区 0）；`falsify-ui.sh` 76 → 84 条；
`uitest.sh` 新增「局长」档 20 条判据（真点击 13 格、落盘、开局传参、每日一局锁、
无尽不挂分母、散场卡夜数）＋ `MODES=` 过滤；样张 `23-lengths` / `24-end-15n`。


## ADR-0016 · 局长的两处锁死：每日一局锁八夜、引导关锁三夜（用户拍板）

**决定**（2026-10-12，他对 §10 第 15、16 条的答复"每日一局锁，引导关轮数少一些"）：
1. **每日一局锁死八夜参照档**。偏好里选了什么都作废：内核构造口 `mode === 'daily'` 直接给
   `DEFAULT_NIGHTS`（与锁标准牌组同一处理），界面 `nightsForRun()` 同口径，
   标题页那一排 `.locked` 且**高亮落回八夜**。
2. **引导关锁最短三夜**，数值钉在 `core/guide.ts` 的 `GUIDE.nights = MIN_NIGHTS`，
   与种子/牌组/难度同一处；`main.ts` 的 `startGuide` 只抄它，界面不再自己挑数。
   `tools/guide-check.mjs` 走的就是这一档。

**为什么三夜而不是"少一些"的别的数**：三夜是 `clampNights` 认的最短档，选它等于"教学局就是
一场遭遇战"。实测风险为零——`guide-check` 报**十节课在第 1 夜就全翻完**（结业那节的门槛是
`cleared >= 1 && seats >= 1`，第一次出铺子就满足），三夜绰绰有余。
代价要说清楚：**短档按设计是更狠的**（三夜的曲线第 3 夜弯到 ×2，终场贵客 8,000 分），
但学员在课上要过的第 1 夜彩头线不分局长都是 300，所以入门那一关没被抬高。

**为什么这件事要写进 ADR**：它把"局长"从一个纯曲线参数变成了**有两处例外的规则**，
而两处例外都是产品决定而不是技术妥协。以后有人想"让引导关跟着玩家选的轮数走"，
会撞到三根钉子：`selftest` 的设计决定锁、`uitest` 引导关档（`BOOT_FIRST` 故意留 `nights:15`
给它装牙）、`falsify-ui` 的注入。

**顺带修的一处文案错**：结业那节气泡原文写"往后每三夜来一位头人改规矩"，
实际是**每一夜的第三场**来一位（`setupStage` 只在 `stage === 2` 摇 `bossId`），差了三倍。

**同一轮他还挑了第 17 条的形式：按局长开专属起手牌组**（五档各一副，`DeckDef.tier` 绑 `tierId`，
`decksFor(nights)` 决定标题页那一排）。没选"奖章/声望加成/短局补贴"三种：前者零平衡影响、
不够"肉鸽丰富"；后两种分别会挪构筑曲线和直接改经济（而钱走不走管道本身还没定）。
**五副的名字与数值都是占位工作名**，等他试玩后定。


## ADR-0017 · 每条快捷键都要有对应的可见控件；禁用态必须自己说清为什么

**决定**：键盘是加速器，不是唯一入口。`main.ts` 里每一条 `keydown` 绑定都必须有一个
**看得见、点得动**的对应控件（原来四条只有键盘或"能点但屏幕上没说能点"：出牌、弃牌、
跳过演出、收幕，全部补齐）。三条硬规矩：
1. 按钮**走同一个函数**（`doPlay` / `doDiscard` / `requestSkip`），不写第二套逻辑；
2. 禁用态要把理由写进 `title`，由一处 `syncActions()` 算，挂在 `renderGauges()` 上；
3. 状态位只留一个写入口（`busy` → `setBusy()`），需要跟着它变的按钮在同一个口子里同步。

**背景**：用户看完局长那一轮之后直接要求"给各种原来只能键盘操控的活动都加上按钮，
不要纯靠键盘"。这一版是 Mac 上双击即玩的自用工具，但鼠标玩家（含触屏版将来）
不该在第一次玩时撞上一堵"这里好像不能点"的墙。

**为什么"能点但看不见"也算 bug**：幕布整块可点、牌桌可点跳过——代码上早有指针路径，
屏幕上却只写"按空格"。这类东西对**测试**更致命：`whenReady` 改成点那颗按钮之后，
性能档实测"点掉结清幕 0 次"，说明它压根不在执行路径上，注入删掉按钮照样全绿。
所以补了独立的 `幕布按钮` 档（`?receipt=1` 让内核真结清一场），而不是把注入删了了事。

**代价与不做清单**：
- 牌桌右下角多一排按钮（`26-actions` 样张量过：不压手牌、不顶掉提示行）。
- **不加**右键菜单、不加拖拽、不做"按钮 + 快捷键"两套状态机；快捷键一律保留，
  按钮只是把同一扇门摆到眼前。
- **不做**触屏适配（那是 §11 backlog 里 iPhone 版的事），但这条规矩让那一版不至于重做交互。

**验证**：`uitest.sh` 新增「鼠标可点」14 条与「幕布按钮」6 条，「跳过演出」27 → 36 条
（三种跳过路径）；`falsify-ui.sh` 86 → 94 条，八条新注入全部以具名判据变红。

**这一轮照出来的两条"测试在骗人"**（都写进纪律了）：
- 第一版 `syncActions()` 只挂在 `renderGauges()` 上，而真点牌走的 `onCardClick()` 只重画
  手牌与读数——**鼠标玩家选完牌「出 牌」还是灰的**，测试却全绿，因为它用 `H.select()`
  （那个测试口顺手做了全量重渲染）。修法是把测试改成点真牌节点，并补上那一次刷新；
  注入"删掉 syncActions 那一行"之后判据从 14 绿掉到 8 绿才算有牙。
  **测试走的路径必须与用户走的路径一致，否则测试口本身就是第二个实现。**
- 幕布那颗按钮第一次注入删掉它仍然全绿：性能档实测"点掉结清幕 0 次"，
  判据根本不在执行路径上。**不在执行路径上的判据等于没有判据**，于是补了独立的「幕布按钮」档。

顺带修一条判据自身的错：原来用"本场分数之差"当"这一手的读数"，
第四手打穿一场时被 `settle()` 清零成 −51（假红），改用内核权威值 `H.lastHand().value`。


## ADR-0018 · 新手引导：讲"此刻屏幕上的那几个数"，不讲定义

**决定**：引导关从十节扩到**十四节**，并且九节课的正文改由 `Lesson.dyn(f)` 现算——
`f` 是从 state 现读的局面上那些数（这一场的彩头、第几夜共几夜、此刻牌型的流水与倍注、
头人是谁、随身几格、货架上那件叫什么、多少钱）。开场卡重写两块正文：
**这间牌局怎么算赢** + **标题页那四排各管什么**。课程表顺序即优先级，窗口三条件
（买得起 / 客人到位 / 不在铺子里）各配一条"只缺它"的判据。

**背景**：他看完之后说"新手引导还是做的不够完善，做详细一点，让第一次接触的玩家也能玩的明白"。
先把"第一次玩的人会问什么"列成清单再补，而不是把现有句子写长。

**为什么必须是真数字**：旧版第一节写"选牌打出的流水 × 倍注，做出**那个数**就算过"——
第一次玩的人不知道"那个数"是几，就得自己去读顶栏并把它和一句抽象话对上。
现在正文直接是"这一场要做 300 分…头顶写着「第 1 / 8 夜」——一夜三场"。
**同一条纪律也管住了实现**：dyn 只读 `Facts`，不许自己算账（渲染层不做算术那条承重墙的延伸）。

**为什么不新增"教程模式"**：这门课要证的判据是"上课的局与不上课的局牌序、流水、
随机数步数逐位相同"（`selftest` 有硬判据 + 注入）。做一个假牌桌、假局面来讲课，
这条承诺就废了，而且玩家学完面对真局面还要再学一次。所以十四节课全部长在**真局**上，
靠窗口条件自动翻页：一把打穿第 1 场的人，"一场要打好几手"那节直接跳过，不拦。

**代价与不做清单**：
- 课程表变长，`tools/guide-check.mjs` 必须能在一局里走完 14 节（现在报
  "第 3 夜 won，13 节真出现 + 1 节自动翻页"）。它原来在"没课要讲"时直接 `break`，
  于是最后几节没出现过也算通过——这条一并修掉。
- 界面档改成**表驱动**（`CHAIN` 每格只写"该长什么样 + 怎么做完"），
  并断言 `H.guide().lessons` 等于那张表：测试与内容不许各说各话。
- **不做**：假牌桌演示、可回看的图文手册、逐课配音、"必须做完才放行"的强制锁。
  课随时能退（「退出引导」一次记完十四节），气泡不吃点击、不盖锚点——这三条都有判据。
- 开场卡上的"约两分钟"这类时间承诺仍然没写（§10 第 5 条未定）。

**验证**：`selftest` 747 → 752；`falsify.sh` 196 → 203（新增 7 条，盲区 0）；
`falsify-ui.sh` 94 → 96；引导关档 54 → 58 条；`guide-check` 全课连得上。


## ADR-0019 · 牌面：点位与花色走代码画的 SVG，不走字体字符

**决定**：新增 `core/pips.ts`——四花色的内联 SVG 图形、2..10 的经典点位表、
J/Q/K 的纹章、A 的双线环。牌面渲染改成：数字牌按点位铺（下半部的点旋转 180°）、
人头牌用真牌的"双头"面板、A 用放大花色 + 环。花色**不再用系统里的 ♠♥♦♣ 字符**。

**背景**：他要"再优化美术细节，牌面细节"。原来所有数字牌都在正中放一个 40px 的字体字符，
于是 9 和 2 只差角标数字——第一次玩的人扫一眼手牌读不出"哪张点多、哪几张能凑同花"。

**为什么必须弃用字体字符**：① 那四个字符是字体给的，换机器换形，`preflight` 只能保证
不引外部素材，保证不了字形一致；② 印刷体的线条与这间牌局的铜版画味不搭（尖角、柄、
双线轮廓都是这套视觉的语言）；③ 字符的颜色与描边没法单独调，做旧时只能整体换色。
项目本来就有先例：客人肖像是 `core/portrait.ts` 代码画的 SVG，并且有可辨性量具。

**为什么点位表放在 core**：它是数据，放 core 才能进 `selftest`（点数等于牌面数字、
中心对称、坐标在 0..1 内、无重叠）与 `falsify`。坐标一律归一化：写死像素的话，
窄屏那档（`--card-w: 78px`）会让点位溢出边框——这是审片档实测出来的。

**代价与不做清单**：
- 每张牌多 2..10 个 SVG 节点（perf 档量过：摆位与重渲染的毫秒数没有可见变化，
  DOM 计数判据按卡数算，不受影响）。
- **七号牌故意不中心对称**（真牌就是这样：多出来那颗落在上半中）。这条"例外"有专门判据，
  否则下一次"顺手统一一下"就会把它改平。
- **不做**：真扑克牌那种整幅人物画（100px 的牌面上画不出来，画了也糊）、
  牌背花纹（现在没有牌背可看的场合）、每档花色的第二套画法变体（走 `:root` 令牌换色）。

**踩到两件事**（都写进判据了）：`.crest` 这个类名早被标题页那颗黄铜徽章占用，纹章撞上之后
整块变金；牌面自己没定 `color`，黑牌继承了页面正文的米金色。**共享类名空间里起名字要先 grep**，
而"单张牌看不出来、52 张摆一起才看出来"——这就是审片档存在的理由。

**验证**：`selftest` 752 → 768（新增 16 条）；`falsify.sh` 203 → 210；`falsify-ui.sh` 96 → 97；
「鼠标可点」加一条牌面投影判据；样张 `27-cardsheet` / `28-cards-eng`。

## ADR-0020 · 抽牌礼：随机挑牌交给玩家抽，但主随机流一步都不许多走

**决定**：事件里"由计算机闷声挑一张牌"的三处（`copyHand` / `mark` / `purge what:'random'`）
改成**把候选扣过来摆一排，玩家抽一张**。三条硬规矩：

1. **候选池的算式只此一份**（`pickPool`）。扇面（`fanOffer`）与执行器（`applyEventOp`）
   都读它——`mark` 那个"只在还没这个花样的牌里挑"的过滤要是写两遍，迟早一处滤一处不滤。
2. **抽牌只换"哪张"，不挪随机流**。每个挑牌位照旧摇那一次 `g.rand.int(pool.length)`，
   有人抽就把摇中的那张丢掉。于是 sim / fuzz / 「让牌局自决」/ 一切不传 `drawn` 的调用点
   账与原来**逐位相同**，同一局"玩家抽"与"牌局自己挑"之后的发牌、铺子、彩头都不动。
3. **一次事件只有一处由玩家说了算**（`DrawPick.spent`）。要落三张的那种（火漆台），
   抽来的算头一张，其余仍由牌局摇；界面那句"其余那几张仍由牌局自己摇"读的是内核给的
   `more` 标志，不许界面自己数 ops。

**背景**：用户一句"要背花纹，随机选择效果拍的时候效果牌翻过去打乱然后玩家抽一张"。
先问清口径（另一种读法是把三选一那面板也改成抽牌），他选**只改"随机挑牌"那几类**——
明着选的三件事照旧摊在纸上，只有本来暗着挑的改成抽。

**为什么摇那一次不能省**：省掉它，"用不用这个仪式"就会改变后面的牌序与铺子——
那等于给同一颗种子开出两副牌。抽牌礼必须是**纯手感层**：它改变玩家的能动性，
不改变随机性。这条有两条判据钉着（步数一致 / 之后的牌堆顺序逐位一致），
注入"某个挑牌位不摇那一位"必须红。

**为什么抛硬币分支里的挑牌不摆扇面**：`coin` 走哪一串要等骰子落地才知道，
提前摆出来的候选是猜的。**摆出来就必须作数**是这一屏的底线，宁可不摆。

**牌背走 CSS 不走 SVG `<pattern>`**：第一版菱格用 `<pattern id="guinea-lattice">` 平铺，
六张扣过来的牌同屏就是六个同名 id，`url(#...)` 只认文档里第一个——摘掉一张其余的纹样跟着变。
底纹改由 `.card.back` 的 background 画（顺带自动跟圆角裁、跟 `currentColor` 换色），
SVG 里只留几何。判据：`牌背里不许有 id 与外部引用`、`牌背的黑桃就是牌面那枚黑桃`。
**但"跟着令牌换色"不等于"跟着令牌就够"**：四种画法摆成一张对照表才发现，暖装饰那套的
`--felt` 与 `--ivory` 几乎同色，中央卡纸直接糊掉。补了一道不依赖令牌的暗边（`rgba(0,0,0,.3)`），
判据与注入各一条。四套画法的对照表从此是牌背的常规审片件。

**账在点击这一刻落地，翻面只是皮**：`drawFromFan()` 先 `chooseEvent`，再把扇面留着演完
那半圈（`busy` 抬着，460ms 后收摊重画）。反过来做（先演再落账）就会有一段"屏幕上还是
上一拍、内核已经变了"的窗口——这个项目的老规矩是内核权威、界面投影。

**代价与不做清单**：
- 扇面最多 6 张（牌堆级的候选池有五十张，摊不开）。判据钉的是"扇面 ⊆ 真候选池"，
  不是"扇面 = 候选池"。
- **不做**：把三选一也改成抽牌（用户拍板）、一夜多件事各抽一次、抽之前允许看牌面
  （看了再抽等于没有仪式）。这三条都进了待定清单。
- **不加新开关**：这一条挂在 `flags.events` 下面。它是事件的表现层，关掉事件它就不存在；
  再开一个开关只会让"关掉等于不存在"这条判据多一个组合要跑。

**验证**：`selftest` 768 → **801**（牌背 7 + 抽牌礼 26）；`falsify.sh` 210 → **227**；
`falsify-ui.sh` 97 → **105**；`uitest` 16 → **17 档**（新增「抽牌礼」35 条），全量 438 条全绿（时钟正常那一轮）；
样张 29 → **31**（`29-backs` / `30-fan`，后者走 `openFan` 那扇门，不是另搭舞台）。

**这一轮照出来的四条**（前三条都是"判据自己不行"，第四条是门禁自己会闪断）：
- **换种子量不出"随机"**：第一版用 10 个种子跑"不抽牌时真的随机"，注入"永远拿第一张"之后
  照样绿——换种子是换一手牌，`hand[0]` 每局都不同。改成同一副手牌只挪随机流才量到。
- **"落的不是那个假 id"是半条判据**：注入 `return 0` 之后玻璃落在 `hand[0]`，
  `hand[0].id !== 9999` 当然成立。要比的是"和什么都不抽时一模一样"。
- **让自检崩掉不算抓到**：注入引用了 `GameState` 上不存在的字段，TypeError 收工。
  注入必须**语法合法、行为错**，才量得到判据。
- **在飞的量不能当判据**：`音频图上待回收的节点 < 20` 是在曲子放着时快照一个数，
  同一档跑五次给出 15/19/19/19/20，界值会被它自己撞红（不是这轮改出来的，但被这轮撞上）。
  改成先停曲、等收尾定时器全跑完再量（实测 0），两句"漏摘滤波器"的注入复验仍是红的。
