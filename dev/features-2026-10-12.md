# 2026-10-12 轮：随机事件（五十条）+ 顺手挖出来的两个真 bug

上一轮交付的是引导关。这一轮做的是用户点名的那件事：**每夜递进来一件事，三件里应一件**，
可以系统代选，有偏策略的也有偏运气的，允许往牌组里塞特殊牌，"设计大胆一些"。
形状与取舍的理由写在 `dev/decisions.md` ADR-0014，这里记做了什么、量到什么、挖到什么。

## A. 一个功能开关，五十条数据

`core/events.ts` 是纯数据：`EventDef`（抬头 / 场景 / 白话账 / 脾气 / ops）× 50 条，
`EventOp` 15 种（钱、声望、改规矩、进计分管道、塞牌、誊牌、落强化火漆、洗花样、带走牌、
收弃牌、重发、客人进出、给信、升牌谱、抛硬币）。动 state 的执行器只有一个：
`core/game.ts` 的 `applyEventOp`。理由很硬——事件要能存档、能重放、能被逐条钉住，
写成回调这三件事一件都做不了。

节奏：每夜至多一次，触发点摇在**本夜第 2~3 次动作**之后（出牌与弃牌合着数，`state.eventAt`）。
候选池用派生流抽（`deriveEventRand(seed, night, 已递次数)`），**不挤动主随机流**；
事件落地时的运气（抛硬币、随机挑一张牌）走主流，因为它真的在改这一局。

待决期间 `play()` 与 `discard()` 一律拒绝——可以慢慢想，但不能把这回事绕过去。
「让牌局自决」按 稳吃 → 靠脑子 → 吃运气 挑，不摇骰，所以"管家会选哪条"是可断言的。

界面：设置 → 玩法实验台第九行「随机事件」；三张 `.ev-card` 摆在 `#eventPick` 那张纸上，
图标是内联 SVG（七个角标一套记号，只用现有令牌，跟着四种画法换色）；
散场那张卡多了「事件回顾」，按夜列出这一局到底应过哪些事、当时实际发生了什么。
音效加了一小声「事件递入」（第 27 声）。

## B. 挖到第一个真 bug：打过的牌每手都在蒸发

接管道时随手写了个"每手数一次四堆合计"的走查，结果是 52 → 48 → 44 → 40。

`play()` 里 `s.table = played` 是**赋值**，上一手那几张不在 hand、不在 discardPile，
只有换场那次 `recycle()` 会收桌面——于是**一场四手，只有最后一手的牌活得到换场**。
拿 10-11 00:57 那份**已发布的桌面构建**跑同一段走查，一样逐手少 4 张，
确认这不是本轮改动引入的，而是发出去的包里就有的行为。

修法：出牌前把旧桌面并进弃牌堆（牌堆抽空时 `refill()` 本来就会把它洗回来接着发）。

```
第1手 52 → 52 → 第2手 52 → 52 → 第3手 52 → 52 → 第4手 52 → 52
```

**这条 bug 一直在替测试撑腰**：界面门禁「性能与泄漏」档里那条
"客人开口的那一声跟着连锁往上爬（mult 或 xmult 至少一种）"，靠的是收租人（人头牌 +7 倍注）
被触发——可那个机器人用 `pickLowest(3)` 永远挑最小的三张，人头牌根本进不了选择。
它以前能响，纯粹是因为牌越打越少、手牌萎缩到只剩人头牌。修好守恒之后手牌一直是满的，
那条判据当场变红。改成让测试真的挑一张人头牌（`pickFace`），"要测的东西"由测试自己摆出来。

## C. 挖到第二个真 bug：随身格可能是客人撑起来的

`fuzz` 在 12 万步里报出一条 `随身超槽`（seed 5370 夜 3，`act=sell`）。
根因不在 `sellSeat` 写错了，而在**套装的 +1 随身是靠两位客人都到场才有的**：
卖掉其中一位，套装散掉，容量当场缩一格，而信还装着三封。
事件里"请走一位客人"那几条（管家的辞呈、绑票）走的是同一条路，所以两边都要守卫。

修法是共用一个谓词 `strandingOnSeatLoss(s, index)`：按"这位不在座之后的容量"算一遍，
装不下就**先腾开再谈退席**（`sellSeat` 拒收并留一句话），事件那条路则改成
"随机挑一位带得走的；一位都带不走就明说，账上写清楚"。不凭空丢玩家的货。

## E. 踩到的坑（都会伪装成"判据坏了"）

1. **异步档自己写轮询 = 少一条 `vcUnstick`**。新档最初自写 `waitIdle`，代打时钟下
   卡在 `busy=true anims=3` 二十秒；换成共用的 `whenReady` 就正常。规矩：**等演出收尾只许用
   `whenReady`**，它认结清幕、认铺子的离开按钮，还会在 3 秒后用 `settleAnims` 把卡在 await
   的动画引用收尾。
2. **`place()` 的存活集漏了调用方**。上一局的动画还在飞时换局，`alive` 只按
   `hand ∪ table` 算，会把**正要摆上桌的那几张**当场从 `cardEls` 删掉，下一句
   `cardEls.get(c.id)!` 拿到 undefined（报成 Promise 拒绝，栈里只看得见 `n.style`）。
   存活集必须并上 `list`。
3. **事件面板靠 DOM 判状态时要先 `H.render()`**。轮询读的是 `state.pendingEvent`，
   屏幕上的三张卡要靠一次投影才存在——读 DOM 之前不投影，判据会因为节奏而不是对错变红。
4. **配方里的 `hz()` 收的是 MIDI 音号，不是赫兹**。新音效写 `hz(196)` 直接被自检的
   可听范围判据拦下来（40~12000Hz）。是 `hz(55)`。
5. **`if (s.flags.events) {` 这种短锚点在文件里有三处**。单行注入只会打到第一处，
   另外两处删了也量不出来——到期那条改成了多行锚点（`falsify.sh` 现在会数命中次数并报
   「锚点有多处，改的是第一处」）。

## H. 第三轮：查接缝（存档边界 + 与其他功能咬合）

第二轮的探针在事件系统内部，这一轮专挑"两个功能咬合的地方"和"存档是外部输入"这条边界。
八项检查，四条真 bug，四条确认没问题（`阈值重复认领`、`凑套装改上限`、`中途读档漂移`、
`50 条 × 4 种残缺局面 = 200 组之后牌局仍可继续`）。

| # | bug | 证据 | 修法 |
|---|---|---|---|
| 1 | 手改的存档可以把"待决事件"带进一局**关着开关**的牌局 | 读档后 `pending=["gas-lamp","duel","wake"]`、`eventAt=2`，而 `flags.events=false` | `deserialize` 在清洗之后：功能关着就把那五格一起清零 |
| 2 | 候选里一个认不出的 id 就能**把牌局锁死** | 自决返回 null、`pending` 仍是那条假 id，之后 `play()` 永远返回 null | `chooseEvent` 摘掉认不出的那条；`autoResolveEvent` 遇到全空候选就收掉待决 |
| 3 | 不在"出牌中"也能应事件（铺子/结清/散场状态） | 把 `status` 摆成 `shop` 再选卡，账上悄悄多了两格修正 | `chooseEvent`/`autoResolveEvent` 都要求 `flags.events && status==='playing'` |
| 4 | 签名宾被事件请走（或被卖掉）之后，`state.signature` 还宣称他在座 | 座位 0、`signature` 仍是 `"payne"`；只有读档时 `save.ts` 才清 | 抽一个 `syncSignature()`，卖座位与事件请走两条路都调它 |

**为什么这四条第一轮没照出来**：第一轮探针问的是"事件自己做得对不对"，这四条都要
**先构造一个不该出现的状态**（改档、摆状态、把签名宾放进座位再请走）。
这个项目的存档路径本来就按"外部输入不可信"写，事件是第一个往 state 里加"待决"这种
**跨帧状态**的功能，所以它天然会踩到那条边界——以后凡是加"待决/挂起"类字段，
第一批判据就该是"读档带着它进来会怎样"。

`falsify.sh` 168 → 175 条，这八根新钉子全部以**具名判据**变红（不是只靠抛错）。


1. **五十条是不是都要留着**。现在有 15 条带 `minNight`（前三夜只递温和的），
   要不要再收窄一点（比如贵客局那拍不递事），等他试玩后再定。
2. **待决该不该真的挡路**。当前是不应下这件事就不能出牌也不能弃牌。另一边是
   "可以继续打，但事件一直挂着"——那会变成玩家永远拖着不选。
3. **每夜一次的频率**。当前八夜最多八条。要更密（每场一次）还是更稀（每两夜一次），
   需要他手感判断。
4. **「让牌局自决」的口径**。当前是"管家按稳吃优先"。也可以改成"跟随本局已选脾气的多数"
   或"纯随机"，那是另一种性格，得他定。
5. **钱要不要走计分管道**。事件刻意不碰这件事（§10 第 3 条还没定）：现在钱只能一次性给扣，
   不能"每手抽 £3"。要不要拉进来，等他决定，决定之后 `score` 那类 op 才允许带 money。

## I. 局长：普通模式可以选打几夜（3～15）

需求原话：**"普通模式可以自定义打牌轮数，三到十五轮总共可自定义范围，设置一定的阈值，
不同轮数对应的最终目标不同，不同轮数开局选择的小丑也略有不同，增加肉鸽的丰富性和可玩性"**。
"轮"按他的选择折算成**整局长度：3～15 夜**（一夜 = 便宴/正宴/贵客三场）。

### 曲线怎么弯：只挪终点，不改形状

`core/lengths.ts` 新增。每一档钉一个**设计值** `finalTarget`（最后一夜贵客局要做到的分），
8,000 → 13,000 → 22,000 → … → 3,330,000，约 1.65 倍递增——短局不是"随便玩玩"，
长局也不是"堆时间"，各有一档该难到哪里去是**写下来的**，不是公式的副产品（有一条判据
逐档核对 `targetOf(最后一夜·贵客) === finalTarget`，13 档一次过）。

从设计值反推一个终点系数 `lengthScale`，再让**每一夜的系数从 1 线性弯到那个终点**
（`nightScale`）。为什么不是"整条曲线乘一个数"（第一版就是这么写的）：八夜参照曲线本身
已经是陡的几何增长，整体缩放会把两端都拧坏——十五夜第一夜只剩 40 分（白送一夜），
三夜第一夜却要 600 分（短局反而更狠）。弯向终点之后人人都从 300 起步，
"长度不同、目标不同"才不是"长度不同、开局也不同"。

八夜那一档分子分母同为 100,000 ⇒ 系数正好 1 ⇒ **参照档逐位不变**：
`nightScale(8, n) ≡ 1`（n 取到 30）、八夜彩头序列仍是 300/800/2000/5000/11000/20000/35000/50000、
`drawOffer(seed, 0, r, 6..9)` 与不传局长**逐位相同**（引导关钉的那个种子照旧）。

### 上线前照出来的一条：长档在无尽里会把彩头做成负数

`nightScale` 是线性式，无尽局会一路打到"最后一夜"之后。长档的终点系数**小于 1**
（十五夜要把 1249 万的参照终点压到 333 万），不夹住 night 的话外推会穿过零：
实测 15 夜档第 20 夜系数 **-0.176**、第 25 夜 -0.485 —— 彩头是负的，
"打输"也算过线。修法是把 night 夹在 `[1, nights]`，过了终点就固定按终点系数弯，
后面交给溢出增长（×2.2/夜）。判据：13 档各推到第 30 夜，彩头必须**全为正且一夜比一夜高**。

### 开局候选随局长偏置（`draft.ts` 的 `lengthWeight`）

只改权重、不多摇一次骰。实测（每档 60 批 × 5 张 = 300 张）：

| 档位 | 长进型 | 翻倍注 |
|---|---|---|
| 3～5 夜 | 7.7% | 29.0% |
| 6～9 夜（参照） | 12.0% | 33.7% |
| 10～15 夜 | 12.3% | 41.3% |

六到九夜恒为 1，所以"参照档的候选不许被搅"这条是量得出来的；偏置方向反过来注入一次，
判据立刻报 `短 53.7% / 参照 45.7% / 长 36.7%`。

### 界面上接的哪几根线

标题页多一排「轮数」13 格（复用 `.pick`，加了 `.pick.len` 收紧内边距——13 格不换行才不把
"入席"那颗顶出屏幕）；说明行跟着报 `档位 · 一句话 · 终场彩头`；牌桌抬头挂分母
`第 Ⅰ / ⅩⅤ 夜`（**无尽不挂**，否则屏幕上是个假终点）；散场卡 `15 夜通吃`；
候选框那句偏置说明只在真的偏过的那几档出现。

2. **按钮走的是同一条函数**（`doPlay` / `doDiscard` / `requestSkip`），不另开第二套逻辑，
   所以"点了没反应"与"按了有反应"不可能各演各的。
3. **`busy` 只剩一个写入口** `setBusy()`：那颗「跳 过」与两颗主按钮的禁用态跟着它一起变。

   幕布那颗「继 续」**故意不绑事件**——它靠冒泡到 `#curtain` 的既有处理器收幕，
   两处各关一次迟早会漂。

跳过那条路现在一次跑三种：按空格 / 点牌桌 / 点「跳 过」，三边都要求"留下的账是同一份"。

## M. 牌背与抽牌礼：随机挑牌那几类，改成玩家自己抽一张

他说"要背花纹，随机选择效果拍的时候效果牌翻过去打乱然后玩家抽一张"。先问清口径
（另一种读法是把三选一那面板也改成抽牌），他选**只改"随机挑牌"那几类**——
明着选的三件事照旧摊在纸上，只有"本来由计算机闷声挑一张"的那些改成抽。

### 哪几处算"闷声挑一张"

`applyEventOp` 里三处，落到事件表上是五条：

| 挑牌位 | 候选池 | 用到的事件 |
|---|---|---|
| `copyHand` | 手牌 | 发牌的手抖 |
| `mark` | 手牌/牌堆里**还没这个花样**的那些 | 碎镜（1 张）、火漆台（3 张） |
| `purge what:'random'` | 牌堆 + 弃牌 + 桌上 + 手牌 | 梗犬（1 张）、扫烟囱的（2 张） |

### 一条设计决定：抽牌只换"哪张"，一步随机流都不许多走

每个挑牌位**照旧摇那一次**（`g.rand.int(pool.length)`），有人抽就把摇中的那张丢掉。
于是：

- 模拟器、fuzz、「让牌局自决」、以及一切不传 `drawn` 的调用点，账与原来**逐位相同**；
- 同一局里"玩家抽"与"牌局自己挑"之后的发牌、铺子、彩头都不动——抽牌礼是纯手感层，
  不是第二条随机性。这条有专门判据（`抽与不抽：主随机流步数一致` / `之后的牌堆顺序逐位一致`）。

候选池的算式只此一份（`pickPool`），扇面（`fanOffer`）与执行器（`applyEventOp`）都读它。
两处各写一遍迟早走样——`mark` 那个"只在还没这个花样的牌里挑"的过滤就是先例。

一次事件只有一处由玩家说了算（`DrawPick.spent`）：火漆台要落三张，抽来的算头一张，
其余两张仍由牌局摇。界面那句"其余那几张仍由牌局自己摇"读的是内核给的 `more` 标志，
不是界面自己数 ops。抛硬币分支里挑的那一张**不摆扇面**（骰子还没落地，摆出来的候选是猜的）。

扇面走派生流（`FAN_SALT`，与事件候选那条错开）：主随机流一根毫毛不动，
`(种子, 夜, 事件 id)` 定了这一排就定了——取消再点回来、刷新重开这一屏都是同一排。

### 牌背：先写成 SVG `<pattern>`，然后自己把它拆了

第一版牌背的菱格走 `<pattern id="guinea-lattice">` 平铺。六张扣过来的牌同屏就是
**六个同名 id**，`url(#...)` 只认文档里第一个——摘掉一张，其余的纹样跟着变。
底纹改由 `.card.back` 的 CSS 画（还顺带自动跟着圆角裁、跟着 `currentColor` 换色），

判据钉死了这条：`牌背里不许有 id 与外部引用`、`牌背的黑桃就是牌面那枚黑桃，不是另画一份`。

### 挖出来五件（三条是自己的判据不行，一条是门禁自己会闪断，一条是四种画法对比表）

1. **换种子量不出"随机"**。第一版"不抽牌时誊抄也真的随机"用 10 个不同种子跑——
   换种子是换一手牌，`hand[0]` 每局都不一样，注入 `rolled = 0`（永远拿第一张）之后
   集合大小照样是 10，判据绿着。改成**同一副手牌只挪随机流**（`for k < i: z.rand.next()`）
   才量到落点在动。falsify 打出来的第二条 BLIND。
2. **"落的不是那个假 id"是半条判据**。`if (i < 0) return 0;` 注入之后仍然绿：
   玻璃落在 `hand[0]` 上，而 `hand[0].id !== 9999` 当然成立。判据要比的是
   **"和什么都不抽时一模一样"**，不是"不等于塞进来的那个数"。
3. **让自检崩掉不算抓到**。注入 `new Rand(s.rand.calls)` 之后直接 TypeError——
   `GameState` 上没有 `rand`。崩溃只证明文件跑不起来，不证明那条性质在被测。
   换成 `new Rand(performance.now()*1000)`（语法合法、行为错）才有判据可红。
4. **音频那条判据在闪断**（不是这次改出来的，但被这次撞上了）：
   `音频图上待回收的节点有界（在飞 < 20）` 是在曲子放着时快照一个数，同一档跑五次
   给出 15/19/19/19/20，界值 20 会被它自己撞红。改成**先停曲、等收尾定时器全部跑完再量**
   （实测 0），注掉一句 `disconnect` 仍然涨到几百 → 两条"越放越重"的注入复验都是红的。
   顺手把「性能与泄漏」的报数拆成"放音中在飞 / 停曲后在飞"两个数。
5. **牌背在暖装饰那套画法里糊成一片**。单看默认那套（绿绒 + 黄铜）没问题，把四种画法摆成一张
   对照表才看见：`deco` 的 `--felt` 与 `--ivory` 几乎同色，中央菱形卡纸直接消失。
   加一道**不依赖令牌**的暗边（`rgba(0,0,0,.3)` 描在卡纸底下），四种画法重新摆一张表复验。
   判据一条（暗边存在且与卡纸同一根中线）+ 注入一条。
   **"整表摆一起"这条纪律又一次比单看有用**——这次是四种画法各摆两张，而不是 52 张。

### 等他判的

- 扇面张数（现在 6）与牌堆级候选要不要摊得更开；
- 抽牌时能不能先看牌面（现在是纯牌背，看完再抽等于没有仪式）；
- 一夜里若两件事都要挑牌，是否每件事各抽一次（现在是"应一件事抽一次"）；
- `more` 那半张牌仍由牌局摇——要不要干脆让 n>1 的那几条改成"抽 n 张"。
