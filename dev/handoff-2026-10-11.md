## 1. 这是什么产品，以及不许商量的约束

一台 Mac 上的维多利亚私人牌局 roguelike（玩法骨架接近 Balatro，**题材、数值、文案全部自研**）。
原生 Swift 只提供一个 WKWebView 壳子；**玩法与界面 100% 是零构建 TypeScript**。

| # | 硬约束 | 怎么验 |
|---|---|---|
| 1 | **任何东西不出这台机器**：无网络依赖、无 AI 调用 | CSP `connect-src 'none'` + `tools/preflight.sh` 实测 |
| 2 | **不用任何外部素材**：图/音/字体一律代码生成（肖像=内联 SVG 剪影，音效=WebAudio 程序合成，字体=系统衬线） | preflight 查无外链、无二进制资源 |
| 3 | **不引入 npm 依赖、不装 tsc**：靠 Node ≥22.18 的 `module.stripTypeScriptTypes` 擦类型 | `tools/build-web.mjs`；源码不许用 enum/namespace/参数属性，跨文件类型必须 `import type` |
| 4 | 交付物必须是**能双击的 .app**，并同步到 `~/Desktop/几尼.app` | `bash build-app.sh` |
| 5 | **命名与美术方向不许替用户决定**，要给可比较的选项 | 见 §10 |

## 2. 架构承重墙（改内核前先读这段）

1. **计分产出一条可重放的事件流**，每个事件带 `after` 快照。界面只是**投影**这条流，
   绝不在 UI 里做算术（`score = chips × mult` 这类式子只能出现在 `core/scoring.ts`）。
2. **`settle()` 不清 `s.table`**：打出的牌要留在桌上直到换场，否则演出与拆解对不上账。
3. **换场必须 `recycle()` 一次性收走 弃牌堆 + 桌面 + 手牌**，漏一堆就会有两张同 id 的牌。
4. **`setupStage` 必须先定头人再读限额**（头人会改手牌上限/花色），顺序错了限额就是错的。
5. **新功能一律走 feature flag，且"关掉 == 不存在"**：这条是有判据的（同一颗种子，
   开关两种状态下牌序/账目逐位相同），不是口头承诺。
6. **单一确定性 `Rand`（mulberry32）+ `calls` 计数器**：任何多消耗一次随机数的改动都会让老存档
   快进落到别的牌上。开局选签名宾用的是**派生流**（`core/draft.ts`），主流一步都不许多走。
   自检里"上课与不上课 `rand.calls` 相等"就是这条的哨兵。
7. **牌是全局自增 id**：读档后必须 `bumpUid()` 推到已有最大值之后，否则"誊抄"会造出撞 id 的牌。
8. **存档是白名单**：`STATE_KEYS` 之外的键一律不认；`JSON.parse('{"__proto__":…}')` 那种
   结构不许用 `Object.assign` 整份吞（会让存档给状态挂原型）。

## 6. 反证纪律（这个项目最特别的一条工程习惯）

- 加判据的同时要能说出**"什么 bug 会让它红"**；写不出来的判据不要加。
- `falsify.sh` 的条目格式：`文件|||原样|||改成|||说明`，**单行字面量匹配、连缩进都算**。
  两个脚本**都会**把条目里的 `\n` 转成真换行（2026-10-11 给 falsify.sh 补上）：同一行文本
  在文件里出现两处时（`discard()` 与 `trimHand()` 的选中项清理就是一字不差的两行），
  单行锚点永远只能打到第一处，删掉第二处也量不出——多行锚点是唯一的出路。
  `falsify.sh` 还会数锚点出现次数，命中多处时报告里打「锚点有多处，改的是第一处」。
- 注入必须产出**合法语法**：`Math.min(12, X)` 改成 `X` 会剩孤儿括号，"文件跑不起来"也被记成
  caught = 假绿。脚本单独计 NOISE/BAD，要当失败处理。
- **新代码会把旧代码"演活"，让老判据变哑**（2026-10-12，缓冲回合带来的）：`bufferRound()` 排在
  `betReprieve()` 之前之后，修行档那条老救援路即使被改坏，"分数还在 / 手牌补满 / 还在 playing"
  三条照样绿——救场的是新代码。判据要钉**是谁干的**：查只有旧路径会留下的那格资源
  （`state.buffer === START_BUFFER`），再让旧路径**连触发两次**（新资源只有 1 发，第二次没得救）。
  两条断言在 `selftest` 的修行档段，注入条目在 `falsify.sh`。
- 报告里 `SKIP 模式失配` = 源码改了、锚点过期（去追锚点）；`BAD 条目写坏` = 字段数不对。
- **在旧锚点上方新增代码会把短锚点抢走**：锚点要全文件唯一，必要时带上下文行。
- bash 数组字面量里 `#` **不是注释**（会被切成条目）；条目里的 `$`、反引号必须转义。
- **两个反证脚本都要先跑一次未注入的基线并全绿**，否则"每条注入都红"是空判据
  （2026-10-10 的假 FALSIFY-UI OK 就是这么来的；2026-10-12 给 `falsify.sh` 补上同一条守卫，
  基线红就 `exit 2` 拒跑并列前 8 条红因）。
- **反证脚本被中途杀掉会留下注入，而且会越攒越多**：还原靠 `trap … EXIT`，进程被
  SIGKILL/整组杀掉时 trap 不跑，当前那条注入就留在源码里；下一轮备份的是**已被污染的源码**，
  于是每中断一次多留一条（2026-10-11 实测 core/ 里同时躺着 8 条：难度 mods 没叠进限额表、
  肖像 CUT 令牌没替换、music 的 heat 加层被删、`rerollPrice` 恒 0……selftest 一次 14 红）。
  排查：拿脚本自己的 INJ 表反查"原样"在不在文件里，再拿 `~/Desktop/几尼.app` 里那份干净构建
  产物（`gen/core/*.js`）对照原文。**杀反证脚本前先确认它跑完了**；真要杀，杀完立刻跑一次
  selftest 看有没有红。
- **复验个别盲区别全量跑**：两个脚本都支持 `ONLY=关键词1,关键词2`（匹配条目说明），
  配 `SKIP_BASELINE=1` 跳过基线（基线刚绿过才行）；ONLY 一条都没匹配上会直接退出非零——
  拼错关键词不该变成"0 条盲区 OK"的假绿。汇总行会写明"表里共 N 条，跳过 M 条，这不是全量门禁"。

## 7. 环境陷阱（无头验证最容易骗人的地方）

1. **WKWebView 的动画时钟只在真的合成帧时才走**。显示器睡着时 `rAF` 不触发、WAAPI 的
   `finished` 永不兑现，「跳过演出」「性能与泄漏」会挂成 `busy=true anims=3` 或 `-1ms`，
   长得和产品软锁一模一样。**先测显示器，再怀疑代码**：
   `CGDisplayIsAsleep(CGMainDisplayID())` / `CGDisplayIsActive`。
2. 报"醒着"也可能中途停摆，所以 `tools/clock-probe.js` 会**真跑一根 150ms 动画**看它能不能
   自己完成；`uitest.sh` 据此决定是否带 `?vclock=1` 代打时钟，并在失败像"卡住"时自动复跑。
   代打下**耗时类判据显式记「未评」**，不混进通过数。
3. **定时器被整秒对齐（App Nap / 负载）不是回归**：跳过生效了（标记收回、无快放痕迹）
   却花掉 1 秒以上 → uitest.js 标 `疑似时钟节流`，uitest.sh 改代打时钟复跑。
   这条用 `uitest=skip&fakethrottle=1` 证明过它会红。
4. **CSS transition 在无头窗口里不走**：靠"去掉 `.hidden`"淡入的元素在 `--shot` 里永远是透明的。
   要拍这种面板，样张查询得同时给 `snap=1` 和一个显式点名开关（课表卡是 `?intro=1`）。
5. **抓帧钩子必须排在 autostart 之后**（`?lesson=1` 这类"直接落在某个界面状态"的钩子），
   否则先开课、再被普通局顶掉，样张里什么都没有。
6. **会动手的轮询会造成假红抖动**：`whenReady()` 不只等动画，它还会点掉结清幕、走出铺子。
   用它断言"此刻屏幕上讲的是哪条"，结论取决于轮询停在哪一步（实测同一份代码 25/25 与 20/25
   都出现过）。判状态驱动的断言请用测试口直接摆状态（`H.clear()` 等）。
7. **门禁自己也要跑得动**：`uitest.sh` 支持 `STOP_FAIL=1`（第一档红就收工，反证扫描用），
   不判手感的档允许 `&speed=12` 压快演出。慢到跑不动的门禁等于没有门禁。
8. `__H.select(n)` 是**切换**不是设置：连调两次等于把牌点回去（测试里踩过）。
   `saveNow()` 有 120ms 防抖：查存档之前先等一下。

## 9. 引导关（第一次玩的那一关）怎么改

十四节课（`core/guide.ts` 的 `LESSONS`，顺序即课程表；2026-10-12 从十节扩到十四节）：
`board 这一场要做几分 → tray 凑牌型 → swap 弃牌 → cash 出牌与拆账 → stage 一场要打好几手 →
shop 货架四件事 → hire 请第一位客人 → satchel 买一件应急的 → raise 抬注 → letter 随身那件怎么用 →
pulse 客人逐个开口 → boss 头人怎么刁难 → ledger 账本与图鉴在哪 → done 结业（含"随时能关，回来续上"）`。
**九节课的正文由 `dyn(f)` 现算**，报的是此刻屏幕上的数（这一场的彩头、第几夜共几夜、
手里这手的流水与倍注、头人是谁、货架上那件叫什么多少钱）——不许退回背定义。

设计要点（改之前先保住这几条）：

1. **上的就是一局真牌局**：`GUIDE = { seed: 20261011, deckId: 'standard', diff: 'gentle', mode: 'run' }`
   全锁死，开局走的是界面里同一个 `start()`，只是多传一个覆盖参数。没有第二套开局代码。
2. **纯投影**：某一节该不该出现 = `open(f)`，算不算过 = `done(f)`，正文 = `dyn(f) ?? body`，
   `f` 全部从 `GameState` 现算
   （`stateFacts()`，界面与 `tools/guide-check.mjs` 共用这一份推导）。玩法一律不读 `state.guide`。
   判据：同一颗种子，上课的局与不上课的局 **牌序 / 流水 / `rand.calls` / 账本 / 日志逐位相同**。
3. **不拦人**：不锁按钮、不替玩家出牌；「这一步我先跳过」「退出引导」随时在。
   `open()` 是窗口：一把打穿第 1 场的人，`stage` 自动翻页。窗口里每一条守卫都要配一个
   "只缺它"的输入当判据（第一版只测了 `cleared`，注入删掉 `!inShop` 照样全绿）。
4. **做到即记账**：`claimGuide()`（web/main.ts）每轮**只记当前那一节**。
   往后扫着记会把 `pulse`（判据是"本场出过牌"）在第 1 场就提前抹掉——本轮真踩过。
5. **换课必须重投影**：铺子里请客人/抬注只调 `renderShop()`，所以 `renderShop()` 末尾补了一次
   `refreshTutorial()`；否则那两节课做完了还挂在屏上。
6. **改课表之后要跑的**：`node tools/guide-check.mjs`（种子还成立吗、十四节是不是全出现过）、
   `MODES=引导关 bash tools/uitest.sh`（58 条）+ `MODES=开机现场`（3 条）、`node core/selftest.ts`
   （课程表自洽 + 顺序翻页 + 存档 + 不改牌局）。
   界面那一档是**表驱动**的（`CHAIN` 每格写"该长什么样 + 怎么做完"），并断言
   `H.guide().lessons` 等于那张表——改了课表不改链，那一条会先红。
7. **种子失效怎么办**：发牌顺序被改动时 `guide-check` 会红并说明卡在哪一节；
   `node tools/guide-check.mjs --search` 会从当前种子往后找第一个能上完整门课的替补。

## 9.5 随机事件（每夜递三张候选，三选一）怎么改

五十条在 `core/events.ts`，动 state 的执行器只有 `core/game.ts` 的 `applyEventOp`。
设计理由（为什么是数据不是回调、为什么候选走派生流）在 `dev/decisions.md` ADR-0014。
改之前先保住这几条：

1. **候选走派生流，运气走主随机流**。`drawEvents` 用 `deriveEventRand(seed, night, 已递次数)`，
   所以"给你看哪三件事"绝不挤动发牌；判据是同一颗种子**开着事件的第一手**与关着的逐位相同
   （含 `rand.calls`）。事件执行时的抛硬币、随机挑牌必须走 `g.rand`。
2. **`ops` 是唯一的真相**。卡片上的分类角标（`eventTags`）与白话账里的 £ 数都由 ops 推导/核对，
   不自建描述字段——自检有一条"文案里每个 £ 数都对得上 ops"专门盯这个。
3. **银钱不进计分管道**。`score` 那类 op 只许带 chips/mult/xmult。§10 第 3 条没定之前，
   钱只能一次性给扣（判据 + 注入各一条盯着）。
4. **特殊牌只用现有的 5 种强化 / 5 种火漆**。新 enum 会断掉"关掉 layers 也要同分"那条 80 手对照，
   而且没有 layers 的路上没有执行者。
5. **待决时 `play()`/`discard()` 一律拒绝**；`pendingEvent` 进存档，读档后 `renderAll()` 会把面板
   重新投影出来。
6. **每夜至多一次**，触发点在 2~3 之间由派生流摇；前置条件不满足就这次不递、下次再试，
   不硬塞玩家应不下来的事。
7. **改完要跑的**：`node core/selftest.ts`、`node tools/guide-check.mjs`（教学局那条判据）、
   `bash tools/uitest.sh`（「随机事件」25 条）、`bash tools/falsify.sh`/`falsify-ui.sh`。
   加事件通常只需要往表里加一条 `EventDef`；**加了新的 `EventOp` 种类就必须在 `applyEventOp`
   里接上，并补一条判据 + 一条注入**，否则那条 op 是"写了没人执行"的死数据。

## 9.6 局长（一局打几夜）怎么改

`core/lengths.ts` 是唯一的账：`LENGTHS` 那 13 行钉"这一档最后一夜的贵客局要做到多少分"，
`lengthScale` 从设计值反推终点系数，`nightScale(nights, night)` 让每一夜的系数**从 1 弯到那个终点**
（第一夜永远 300，八夜那一档逐夜都是 ×1）。改数值只动 `LENGTHS`；改曲线形状是另一件事，
要顺带重跑 `node core/sim.ts --nights=N` 看各档下界走到哪。

三处接线，缺一不可，都有判据：
1. `game.ts` 的 `limits()` 里那行 `add({ targetScale: nightScale(s.nights, s.night) })`
   ——垫在难度之前，和它同一层；
2. `leaveShop()` 里 `s.night >= s.nights` 判胜；
3. `draft.ts` 的 `lengthWeight`（六到九夜恒为 1，参照档的候选不许被搅）。

界面只有一个口子读局长：`main.ts` 的 `nightsForRun()`。标题页高亮、说明行、候选偏置、
开局传参全走它，所以"每日一局锁八夜"只需要改这一处。**别在界面里另算一遍夜数**——
屏幕上亮着一个不会跑的数字，比不锁更糟（这条有判据，也有注入钉着）。
**局长给的奖励是五副专属起手牌组**（`content.ts` 的 `DeckDef.tier` 绑 `lengths.ts` 的 `tierId`）：
每一档在通用五副之外多摆一副，`decksFor(nights)` 决定标题页那一排，`deckLegal(id, nights)` 是
开局与读档共用的那一份判据——对不上就落回标准局。**屏幕上不许留一个点得动、进不去的选项**：
换档时选不到的那副当场退回标准局（与签名宾同一口径）。

两处**故意锁死**：每日一局锁八夜参照档（`nightsForRun` 里那一刀，内核构造口也兜一道）；
引导关锁**最短三夜**，而且那个数钉在 `core/guide.ts` 的 `GUIDE.nights` 里，与种子/难度/牌组同一处
（`tools/guide-check.mjs` 走的就是这一档）。改引导关的轮数要连课表与 guide-check 一起改，
`selftest` 有一条专门把它钉成设计决定。

## 9.7 抽牌礼（随机挑牌那几类改成玩家抽一张）怎么改

口径在 `core/game.ts` 三个函数里，界面只读不算：

- `pickPool(s, op)`：**候选池的唯一算式**。`copyHand` 给手牌、`mark` 给"还没这个花样"的那些、
  `purge` 给"牌堆→弃牌→桌上→手牌"这个扫描顺序（手牌排最后，别顺手抽走玩家正用的牌）。
  扇面与执行器都读它，写两遍迟早一处滤一处不滤。
- `fanOffer(g, id)`：这条事件要不要抽、抽哪些。三道门与 `chooseEvent` 同一套
  （开关 / 在出牌中 / id 在候选里）；只走**顶层 op**，`coin` 分支里的挑牌不摆扇面。
  顺序走派生流 `deriveFanRand(seed, night, 事件 id)`（`FAN_SALT` 与事件候选错开），
  最多 `FAN_SIZE` 张。
- `drawnAt(pick, pool)` + `DrawPick.spent`：抽来的那张只给**第一个候选池含它的挑牌位**用，
  用完作废。每个挑牌位**照旧摇那一次** `g.rand.int(pool.length)`，有人抽就把摇中的丢掉——
  所以"用不用仪式"不改变随机流位置，sim / fuzz / 自决 / 老档逐位不变（ADR-0020 的决定点）。

界面：`takeEvent()` 先试 `openFan(id)`，摆得出扇面就等玩家抽，摆不出就直接落账。
`drawFromFan()` **先落账再演翻面**（内核权威、界面投影；`busy` 抬着，460ms 后收摊）。
牌背在 `core/pips.ts` 的 `BACK_ART`（只有几何），菱格与圆点在 `.card.back::after` 的 CSS 里——
**别改回 SVG `<pattern>`**：六张牌六个同名 id，`url(#...)` 只认文档第一个，摘掉一张其余纹样跟着变。

改完要跑的：`node core/selftest.ts`（§19 那 26 条）、`bash tools/uitest.sh MODES=抽牌礼`、
`bash tools/falsify.sh ONLY=扇面,抽来的那张,不摇位`、`bash tools/falsify-ui.sh ONLY=扇面`。
**加新的"随机挑牌"op 时**：在 `pickPool` 里加一条分支，`fanOffer` 与执行器就都认得了；
只改执行器不改 `pickPool`，那条 op 会闷声挑牌而不摆扇面（判据 `五条随机挑牌的事件全都摆得出扇面`
量的是现表，新 op 要补一条）。

## 10. 等用户拍板的（**不要替他决定**）

产品/玩法：
1. 加注粒度是"每场一押"还是"每手一押"（`dev/phase0-pipeline.md` §6）。
2. 缓冲回合已经按他要求落地（`dev/decisions.md` ADR-0013：开局 1 发、先于付费续命、不重抽贵客）。
   **还没定的**：每人几发才算合适、能不能靠声望/铺子再赚回来。
3. 三个只跟钱有关的 hook 要不要拉进计分管道。

引导关（本轮新增，`dev/features-2026-10-11.md` §F）：
4. 老用户升级后第一次启动要不要被课表卡拦一次（当前：**要**，`o.guide === true` 才算上过课）。
5. 课表卡上写不写"约两分钟"（实测走完约 40 秒）。
6. 教学局要不要"上完课就散场另开正式局"（当前：留档，可继续打完八夜）。
7. 结业那节气泡钉在牌桌正中还是别处。

美术/音效：
8. 肖像底色是内联样式，所以四种画法不会给肖像换色（已知限制，要不要打通）。
9. 音效音量与背景乐音量要不要拆成两条滑杆（现在是一条总音量 + 背景乐固定比例）。

随机事件（2026-10-12 新增，`dev/features-2026-10-12.md` §F）：
10. 五十条要不要都留着：现在 15 条带 `minNight`（前三夜只递温和的），要不要再收窄。
11. 待决该不该真的挡路：当前不应下这件事就不能出牌也不能弃牌。
12. 每夜一次的频率要不要改（当前八夜最多八条；可密到每场一次，或稀到每两夜一次）。
13. 「让牌局自决」的口径：当前是"管家按稳吃优先"，也可以跟随本局已选脾气的多数，或纯随机。

抽牌礼（2026-10-13 新增，`dev/features-2026-10-12.md` §M 与 `dev/decisions.md` ADR-0020）：
13.5 ~~三选一要不要也改成抽牌~~ → **他定了：只改"随机挑牌"那几类**，明着选的三件事照旧摊在纸上。

      （现在只有头一张由玩家定，其余仍由牌局摇）。

局长（2026-10-12 新增，`dev/features-2026-10-12.md` §I 与 `dev/decisions.md` ADR-0015）：

    不是公式的副产品；他改任何一格，自检会照新值判（`lengths.ts` 的 `LENGTHS`）。
15. ~~每日一局要不要锁~~ → **2026-10-12 他定了：锁**（"同一天同一局"含局长，与锁牌组同一理由）。
    "当天的局长由日期派生"那条路作废。
16. ~~引导关要不要跟着玩家选的轮数~~ → **2026-10-12 他定了：轮数少一些**，实现成锁最短三夜
    （`GUIDE.nights = MIN_NIGHTS`）。实测十四节课在第 1 夜就全翻完，三夜绰绰有余。
17. ~~局长要不要给独立奖励、给哪一种~~ → **2026-10-12 他挑了「按局长开专属牌组」**，已落地：
    五档各一副（短局 一手到位 / 中局 半班底 / 正局 庄家账 / 长局 长灶 / 深夜局 守夜人），
    只有对应那一档摆得出来，错配一律落回标准局（构造口与读档两处都挡）。
    **还没定的两件事**：
    - **五副的名字全是占位工作名**（与「几尼」同一状态），等他定；
    - **数值只过了下界机器人**：五档之间谁更难、专属牌组会不会让某一档变成唯一正解，
