# 几尼 1.2.0 · 委托与来信

2026-10-17。用户确认的第一批：12 份宾客委托、4 条连锁故事、8 种稀奇牌、4 位客人。
本轮版本 1.2.0 / build 5，bundle ID 不变。本机试玩渠道，不做公证或上架。
上一版桌面包保存在 Codex 工作目录 `work/guinea-backup-1.1.0/几尼.app`。

## 如何体验

开局页点击「经营奇遇」，再入席。该预设统一开启 club、events、sets、growth、adjacency、layers；
关闭预设回到基础规则。玩家仍可在设置自定开关，正在打的局使用自己的 flags 快照。
新增开关默认关闭；每日一局和教学局禁用委托、故事，不改变已有固定教学流程。

牌桌顶栏「委托簿」随时打开纸面侧栏，展示接单、进度、奖励、故事前情与结局。
夜初自动打开；可以直接关闭并开打，不强制接单。两个候选、每夜至多一份，首个出/弃牌动作后不再接受。
普通委托失败没有额外惩罚。达成后选择一次奖励，并另得 1 声望；满座/牌组满仍可选银钱。
未领取的已达成奖励会阻止离开当前铺子，避免换夜覆盖；商店提供明显的领奖入口。

## 内容

### 十二份委托

节俭晚宴、偏爱红心、不重复的节目、黑领结之约、贵客的肖像、三张小宴、珍奇展览、
账房的信任、只凭手艺、成双的请柬、满桌都是好牌、有胆识的主人。

收益有三类自选：已解锁牌谱立即升级、八种新增稀奇牌选一张、四位新客人定向邀请。
每份另有 £6～£8 的银钱替代奖励。领取客人导致套装限额改变时，同步当前剩余次数及新增手牌。
只凭手艺/节俭/储蓄在第三场结清才核定；重做不抹掉本夜已使用的物品、弃牌等代价。
计分参与者取真正 card 事件的 ID 集合：重诵不把一张牌算作两张，被贵客挡住的不算。

### 四条故事

失踪的账本、午夜邮差、旧牌匣、空席的约定。每局由种子确定一条，共 20 种结局。
可提前结束或继续两次跨夜选择；同一夜不能跳读下一章。
报酬/花费在选项中展示，不够钱的分支禁用。没有需要真实空出座位的隐形条件。
故事每个待选章节至少有一个不用付钱、不会塞满牌组的出口。

随机事件待决时，委托奖励与故事选择暂时禁用，避免先花掉资金再以旧条件领取事件利益。
故事进度不抢主随机流；获得牌组奖励后洗牌属于真实玩法动作，使用主随机流并保存步数。

### 八种稀奇牌

- 接力：前一张计分牌同花，+25 流水。
- 收藏：结清时留手积 1 层，每层计分 +20 流水，上限 4 层。
- 拾遗：弃掉积 1 层，每层计分 +3 倍注，上限 4 层。
- 债券：计分 ×0.9 倍注；每次出牌首次计分兑现 £2，一张牌最多兑现 3 次，重诵不额外付钱。
- 封缄：本张带火漆时，计分 +30 流水。
- 彩窗：计分牌凑齐四种花色时，×1.5 倍注。
- 小宴：总出牌数不超过三张时，计分 +5 倍注（陪牌也计入总张数）。
- 后备：出牌时待抽牌堆少于十五张，计分 +40 流水。

新牌来自委托自选或故事结局；原六种仍来自随机事件。共十四种，图鉴全部解释。
蓄力/兑现次数存入卡牌 `charge`，界面角标和可访问说明显示即时进度；复制保留已有进度。

### 四位新客人

契约律师（履约数加倍注，上限 12）、修复师艾达（收藏/拾遗蓄力加流水）、
午夜邮差（出牌中相邻同花加流水）、灰手套赞助人（本夜履约后，每场结清 £4）。
四位有独立肖像、刻印和 tag，在经营奇遇的商店或委托奖励出现。
不进入基础牌局的候选池，以保留旧种子下的基础发牌/铺子行为。

## 架构与存档

- `core/contracts.ts`：委托定义、夜内统计、候选派生流。
- `core/stories.ts`：章节、分支、实际奖励操作数据。
- `core/club.ts`：有界状态和外部输入校验；不引入 DOM、时间或随机副作用。
- `core/game.ts`：唯一的接单/领奖/故事执行入口，状态转换、派钱、加牌均由内核完成。
- `web/club-view.ts`：侧栏投影；主界面只绑定按钮和保存，不重算达成条件。
- `run-summary`、分享文案、散场页和 PNG 增加履约数量、履约记录、故事结局与关键选择。

save v1 兼容旧档：缺 club 时按开关初始化，默认关则为 null；缺 charge 按零处理。
新增决策类型 contract/story；归档最多 60 条，战报节选最近 15 条，关键选择最多 6 条。
报告字段向后兼容，旧战报可继续查看。新内容的存档不保证能由旧版 1.1.0 打开。

## 同批修正

修正出牌/幕卡跨局异步归属、隐藏界面的焦点与按钮处理、重复跳过收尾、两对/葫芦计分顺序、
每手阈值认领、皇家与同花顺共用等级、事件当前次数同步、满座负片购买、双生的经济挂载点、
每日禁止无尽、复盘最高流水一致、终局在演出前持久化战报。

牌 ID 改为实例分配，异常大 ID 会从空闲安全 ID 重新分配；限额加合理上下界。
存档修正表限制字段与数值类型，rerolls 与内核统一接受安全整数。
原生资源边界按根目录分隔符核对并解析符号链接；开发服务非法 URI 返回 400，构建用 fileURLToPath。

事件若耗尽最后一次出牌机会，立即走既有缓冲/修行或判负；事件降低彩头使现有流水达标时立即结清。
手选、自决及抽牌礼三条界面路径都衔接对应结算。

## 验收入口

```sh
node core/selftest.ts
node core/fuzz.ts 60
node tools/club-check.mjs
bash tools/falsify.sh
bash tools/uitest.sh
```

新增 `tools/club-uitest.js`（真接单/领奖/故事/原生 PNG）、`tools/club-regression-ui.js`（跨局、事件终局）。
原生验收必须串行。测试用 nonPersistent WebKit，不清玩家数据库。异步脚本写入 `window.__UITEST_RESULT`；
壳只执行脚本一次，然后轮询该字段，不会自动重跑脚本。

最终数字、截图和签名核对以交付目录 `outputs/几尼-1.2.0-验收` 的日志与 manifest 为准。
不把首轮失败、重试、未评耗时混写成一次全绿扫描。审批额度曾使完整原生测试未能启动，随后已恢复执行。
